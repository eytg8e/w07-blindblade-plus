### 직선 복도 씬

- 2026-10-10: 적 처치 후 끝 문을 F로 열고 통과하면 Stairwell로 이동한다. 계단 위 문은 TCorridor로 연결된다. [스테이지 이동 명세](스테이지_이동.md) 참고.

- 기능 설명: 폭 4m, 길이 24m, 벽 높이 3m의 단순한 1자 복도에서 플레이어와 근접 적 한 명을 마주 배치한다.
- 동작 조건 및 처리 흐름: Assets/Scenes/StraightCorridor.unity를 열고 Play한다. 플레이어는 (0, 0.1, -10), 적은 (0, 0, 10)에서 서로 바라보며 시작한다. 기존 근접 적은 감지 범위에 들어오면 추적·공격한다.
- 구현 상태: 씬과 전용 NavMesh 생성 완료. 기존 MainMap의 저장되지 않은 변경을 보존하면서 복사해 플레이어·세션·전투 서비스 구성을 재사용했다.

#### 연결 및 협업

- 연결된 기능: 기존 플레이어 입력·전투 서비스·체력·걸음 보행·착지 시 윤곽선·FMOD Listener 및 공통 SoundLibrary.
- 공유하는 코드 및 상태: 이동과 공격은 기존 컴포넌트를 재사용하고 복도 전용 CorridorRoundController가 패배 및 재시작을 담당한다. NavMeshSurface는 Corridor 자식의 Collider만 수집하고 적의 agentTypeID에 맞춰 베이크했다.
- 중복 또는 충돌 사항: 원본 MainMap과 적 프리팹은 변경하지 않는다. Build Settings에 StraightCorridor를 추가했다. MainMapSession은 재시작 때 감각 매니저가 종료 상태이면 다시 초기화한다.
- 승인 필요 사항 및 결과: 사용자가 단순 직선 복도 씬 생성을 요청했다. 기존 A 자동 구현과 기능별 자동 커밋 지침을 따른다.

#### 검증

- 새 씬 직접 Play 시작에서 플레이어 접지·한 걸음 이동·착지 1회·윤곽선 영역 1개·감각 매니저 준비 상태·적 타깃 연결을 확인했다.
- 적 NavMeshAgent.isOnNavMesh=true, 복도 양 끝 사이 NavMesh 경로 PathComplete, 적 1명 및 Listener 1개를 확인했다. 실제 공격 애니메이션·피해 교환은 이번 검증에 포함하지 않았다.
- 씬 재시작 때 지속 Game의 감각 매니저가 이전 씬 종료로 비초기화되므로 MainMapSession.Start에서 초기화 상태를 복구한다.
- 검증 후 Play를 종료하고 원본 MainMap의 미저장 상태를 보존했다. 테스트 코드와 새 Editor 스크립트는 작성하지 않았다.

- 적 발자국: MainMapSession.Show Enemy Footsteps를 복도 씬에서 켰다. 기존 Enemy_SingleMelee의 FootstepEmitter와 공통 Footstep 프리팹을 사용하고 Default 지면 레이어를 검사한다. Play에서 적 0.8m 이동을 재현하여 발자국 1개 및 웨이브 포함 효과 2개를 확인했다. 이 시각 검증에서는 FMOD 초기화 실패 영향을 분리하기 위해 적 사운드 구독을 런타임에서 잠시 비활성화했고 Play 종료로 복구했다.

#### 선제 피격 GameOver와 재시작

#### 순찰 후 감지 돌진

- Enemy_CorridorEnd의 감지 반경을 20m에서 6m로 줄였다. 시작 시 플레이어와 적의 거리가 약 20m라 감지되지 않고 기존 EnemyPatrol이 배치 위치 z=10부터 z=7까지 3m 왕복 순찰한다. 순찰 속도는 EnemyMotor.Move Speed=1.5m/s다.
- 복도 씬의 적에 기존 EnemyChargeAttack을 추가하고 EnemyAttackSelector.Patterns를 돌진·근접 공격으로 구성했다. 2~6m에서 돌진, 2m 이내에서는 기존 근접 공격을 사용한다. EnemySensor의 거리·시야 검사와 Controller의 기존 상태 전환을 사용하며 공통 적 프리팹 및 스크립트는 변경하지 않았다.
- 돌진 설정: 전조 0.5초, 속도 12m/s, 실행 0.65초, 후딜 0.15초, 쿨타임 1.5초. 조준은 전조 시작 위치로 고정하므로 플레이어가 전조 중 회피할 수 있다. 돌진이 끝나면 순찰/접근 속도 1.5m/s로 복원된다. 차폐·범위 이탈·수색은 기존 적 규칙을 따른다.
- Inspector 조절 위치: Enemy_CorridorEnd → EnemySensor.Detection Range, EnemyPatrol.Distance/Wait Duration, EnemyMotor.Move Speed, EnemyChargeAttack의 전조·속도·시간·사거리.
- 검증: Play 시작 후 Patrolling과 실제 위치 z=8.49를 확인했다. 적 기준 6.2m에서 CanSeeTarget=false, 5m에서 true 및 Telegraph/Attacking 전환을 확인했다. 프레임 관찰에서 돌진 속도 12, 종료 이벤트 발생과 속도 1.5 복원, 적 위치 z=3.56 및 후속 근접 공격에 의한 GameOver를 확인했다. Unity 컴파일 상태 completed, errors=[], compilationFailed=false. 검증용 플레이어 이동과 관찰은 런타임에서만 적용했고 Play 종료로 복구했다.

- 플레이어가 첫 공격을 성공시키기 전 적에게 실제 피해를 받으면 즉시 패배한다. 단순 헛스윙은 선제 명중으로 계산하지 않고, 가드로 막은 공격은 피해 이벤트가 없어 패배하지 않는다. 첫 명중 후에는 기존 체력 사망 시 패배한다.
- Assets/Scripts/Maps/CorridorRoundController.cs는 PlayerController.ActionEvent의 HitConfirmed를 기록하고 PlayerHealth의 DamageReceived를 구독한다. 적 공격자의 EnemyHealth를 확인한 뒤 ShowGameOver를 호출한다.
- GameOver는 입력을 끄고 플레이어를 Dead로 전환하며 Time.timeScale=0으로 게임을 멈춘다. 커서를 풀고 GameOverCanvas의 재시작 질문을 표시한다. Screen Space Camera Canvas를 사용하여 윤곽선 렌더링 위에 UI를 표시한다.
- RESTART는 현재 씬을 다시 로드하여 체력·배치·첫 명중 기록을 초기화한다. NOT YET은 패배 화면에 머물며 나중에 재시작할 수 있다. 종료 시 기존 시간 배율과 커서 상태를 복구한다.
- Inspector: CorridorRound의 Player, Damage Receiver, Input, Panel 및 두 Button 참조를 연결한다. 체력과 가드는 기존 PlayerHealth 설정을 사용한다.
- 검증: 적의 실제 DamageContext 전달 시 GameOver·시간 정지·커서 표시를 확인했고, 가드 시 패배하지 않는 것을 확인했다. Game View 캡처에서 제목·질문·두 버튼 표시를 확인했다. 재시작 후 체력 100·입력 활성화·감각 매니저 준비 상태 복구를 확인했다.

#### 적 캡슐 표시 제거 (2026-10-10)

- Enemy_SingleMelee, Enemy_SingleRanged, Enemy_MultiPattern, Enemy_RhythmCharge 프리팹의 Placeholder 캡슐 MeshRenderer만 비활성화했다. GameObject와 CapsuleCollider, 이동·공격·발걸음 컴포넌트는 유지한다.
- StraightCorridor의 Enemy_CorridorEnd에는 기존 프리팹 연결을 통해 자동 반영된다. 캡슐의 면과 윤곽선은 렌더링하지 않고 발자국은 기존대로 생성한다.
- 검증: Unity Editor에서 Enemy_CorridorEnd의 rendererEnabled=false, CapsuleCollider.enabled=true, GameObject 활성 및 해당 Collider.Raycast 명중을 확인했다. 네 프리팹 변경은 각각 MeshRenderer.m_Enabled 한 항목뿐이다.
