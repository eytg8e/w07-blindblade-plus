#### 연결 및 협업

- 승인: 사용자가 A 자동 구현 모드로 .anim/Animator 전환을 선택했다.
- 이벤트 구독자: PlayerWeaponDebugVisual. 발행자: PlayerController.ActionEvent. PlayerActionEvent의 Stage, State, ActionId를 읽는다.
- ChargeStarted/ChargeReady → Charge. ChargeCancelled/ChargeEnded → ChargeRelease. GuardStarted/Succeeded/Ended → GuardEnter/GuardDeflect/Rest.
- AttackStarted → Normal1~3. DashStarted → SheathedHold. SlashStarted → IaidoDoubleSlash. Recovery → Rest.
- 가드 성공은 기존 시스템이 PlayerController.NotifyGuardSuccess()를 호출해야 한다. 표현이 성공 판정을 만들어내지는 않는다.
- 강공격은 마지막 베기에서 기존 단일 판정 1회 유지. 드라이버 → IaidoSlashImpactEvent() → NotifyIaidoSlashImpact(actionId) → 기존 적 서비스 → HitConfirmed/DeathConfirmed 흐름이다.
- 드라이버의 GetPresentationTiming(PlayerAttackKind, out float impactTime, out float duration)과 GetPresentationElapsed(int actionId)를 읽는다.
- 새 팀원 연동 이벤트는 없다. 적/발걸음/맵 코드는 변경하지 않았다.
- Animator.fireEvents=false: 현재 클립은 시각 표현만 담당한다. 클립에 피해용 Animation Event를 추가하지 않는다. 향후 이벤트 방식으로 판정을 이관한다면 드라이버 중복 발행을 제거하는 별도 설계가 필요하다.
- 기존 가드 확인 도구가 참조하는 GuardTransitionTime, IsAtGuardPose, IsAtRestPose, HasGuardSuccessColor는 유지했다. 포즈 도착 프로퍼티는 이제 해당 Animator 상태 및 전환 완료 여부를 나타낸다.

#### 직접 편집하는 방법

1. Play를 종료한다.
2. Hierarchy의 플레이어 카메라 아래 PlayerWeaponRig를 선택한다. PlayerController가 붙은 부모가 아니라 Animator가 붙은 이 루트를 선택한다.
3. Window → Animation → Animation을 연다.
4. 상단 클립 목록에서 GuardDeflect 또는 편집할 클립을 선택한다.
5. Curves 탭에서 Sword 또는 Saya의 Position / Rotation을 펼친다.
6. 타임라인을 스크럽하고 키 위치 또는 탄젠트 손잡이를 움직인다. Scene 뷰와 Game 뷰를 함께 보며 조정한다.
7. 저장 후 Preview를 끄고 Play에서 조작감을 확인한다. 클립 수정은 공유 에셋 수정이므로 이 프리팹을 사용하는 모든 플레이어에 적용된다.

- Project에서 PlayerWeaponRig.prefab을 열어 프리팹 루트를 선택해도 편집할 수 있다.
- .anim 파일은 Assets/Animations/PlayerWeapon/Clips에 있으며 FBX 내부의 읽기 전용 클립이 아니다.
- 각 클립은 Sword/Saya 각각 위치 XYZ와 Euler 회전 XYZ, 총 12개 커브를 가진다. 커브당 2~11개 키로 초기 포즈를 옮겼다.
- Sword/Saya 이름과 계층 경로를 바꾸면 커브 바인딩이 끊어진다.
- 런타임 자동 생성/덮어쓰기를 하지 않는다. 사용자가 수정한 커브는 유지된다.
- 기존 Inspector의 Rest Local Position, Guard Deflect Angle 등 포즈 수치는 제거했다. 이제 해당 클립의 커브를 수정한다.
- Hierarchy에서 Player Camera가 아니라 그 자식인 PlayerWeaponRig를 선택한다. Animator는 PlayerWeaponRig에 붙어 있고 Animation 창의 오브젝트 선택이 비어 있으면 클립 커브를 열어도 씬 인스턴스에 미리보기 되지 않는다. Scene/Game 뷰 업데이트 확인 시 Preview 모드를 켜고 해당 리그를 선택한다.
- Animation 창의 Record는 모델 Transform 변경을 키로 기록할 때 사용한다. 단순 커브 수정에는 Record를 켤 필요가 없다.

#### 설계와 학습

1. AnimationClip과 Animator의 역할
   - Clip은 시간에 따른 위치/회전 데이터다. 곡선을 바꾸면 검이 지나가는 경로와 회전이 바뀐다.
   - Controller는 이 클립을 상태로 보유한다. 게임 상태가 이미 PlayerController에 있으므로 전환 화살표를 중복 구성하지 않고 C#의 Play/CrossFadeInFixedTime으로 상태를 선택한다.
   - CrossFade는 이전 포즈와 새 클립을 짧게 섞어 전환을 완만하게 한다. 코드에서 검 Transform을 다시 덮어쓰지 않는다.
   - 대안은 Animator 파라미터/전환 조건으로 모든 상태 전환을 구성하는 방식이다. 현재는 기존 전투 상태와 충돌을 줄이기 위해 이벤트로 직접 선택한다.

2. 차징 시간
   - Charge 상태는 ActionProgress를 Motion Time으로 사용한다.
   - 실제 ChargeProgress가 0.5이면 클립의 가운데를 평가한다. 클립의 1초는 저작 기준이며 실제 재생 시간은 PlayerController의 Minimum Charge Time이 결정한다.
   - 초기 0~0.4는 정렬, 0.4~1은 삽입이다. 커브 키의 시간 위치를 옮기면 이 비율을 직접 바꿀 수 있다.

3. 공격과 판정 동기화
   - 일반 및 발도 공격 상태도 ActionProgress를 Motion Time으로 사용한다.
   - 드라이버의 실제 시간 중 적중 전 구간은 클립 0→Impact Progress로, 적중 이후 구간은 Impact Progress→1로 매핑한다.
   - 일반 Normal Impact Progress=0.375, 발도 Iaido Impact Progress=0.5833333이다. 초기 클립에서 각각 0.15/0.4, 0.42/0.72에 해당한다.
   - 실제 판정 시간은 드라이버의 Normal Hit Time / Iaido Hit Time, 실제 행동 종료는 Normal Action Duration / Iaido Slash Duration이 결정한다. 클립의 마지막 키를 늘리는 것만으로 전투 행동이 길어지지는 않는다.
   - 강공격 마지막 베기 키를 클립의 0.5초로 옮겼고 전체 길이가 0.72초라면 Iaido Impact Progress를 0.5/0.72 ≈ 0.6944로 맞춘다. 첫 베기에 맞추면 사용자가 선택한 마지막 베기 판정과 어긋난다.
   - 일반 공격 세 클립은 같은 Normal Impact Progress를 사용하므로 각각 같은 정규화 지점에서 타격하게 편집한다.
   - Recovery 값은 변경하지 않았다: 일반 0.25초, 발도 적중 0.15초 / 빗나감 0.7초 / 벽 충돌 0.9초.

4. 수명과 시간
   - OnEnable/OnDisable의 이벤트 구독을 짝지었다. Start의 Intro는 인스턴스 시작 1회이며 재활성화 시 반복하지 않는다.
   - IsPaused이면 Animator.speed=0으로 시각 재생을 멈추고 시각 타이머도 멈춘다. 사망 이벤트는 Dead로 전환한다.
   - DefaultExecutionOrder(100)으로 기존 기본 순서의 행동 드라이버 이후에 표시 파라미터를 갱신한다.
   - MaterialPropertyBlock으로 가드 성공/준비 완료 색상을 인스턴스에만 적용한다. 공유 재질 에셋의 색상을 직접 변경하지 않는다.
   - Show Weapon은 렌더러만 숨긴다. 전투 및 애니메이터 진행은 유지된다.

#### 확인 결과와 한계

- 이번 전환: Unity 6000.0.55f1에서 컴파일 오류 0건 확인.
- 사용자의 가드 검증 요청에 따라 기존 PlayerSandboxScenarioControls F8 GuardValidationRoutine을 Play Mode에서 실행했다. GuardCheck PASS: started=True, guardPose=True, blockQuery=True, successEvent=True, successColor=True, endEvent=True, restPose=True.
- 첫 F8은 전투 이벤트와 자세 복귀가 성공했지만 HasGuardSuccessColor가 페이드 중인 색상에 대해 너무 엄격한 비교를 해 실패를 표시했다. 판정값을 _guardFlash > 0.05로 바꾸고 다시 실행해 PASS를 확인했다. 실제 색상 페이드는 유지된다.
- AnimationMode Preview에서 GuardDeflect 0.155초를 샘플링해 Sword 위치/회전이 변하고 Scene View 및 Game View에 반영되는 것까지 확인했다. 빈 Selection이 원인이었으며, PlayerWeaponRig 선택과 Preview 상태를 현재 복원했다.
- 에셋 연결 확인: 클립 13개, 각 12개 커브, 프리팹 Animator/Controller 및 씬 참조 저장 완료. Charge와 공격 4개 상태의 Motion Time 연결 확인.
- PlayerDebugSandbox의 PlayerWeaponRig를 선택하고 Animation 창에 GuardDeflect를 열었다.
- 이번 클립 전환 이후 Play Mode 입력/전투 회귀 테스트와 빌드는 실행하지 않았다. 이전 프로시저 구현에서 확인한 공격 1회 판정 등의 결과를 이번 전환의 검증 결과로 간주하지 않는다.
- 실제 손/팔, 다른 화면 비율/FOV, 벽 가림, 적 AI의 가드 성공 연동은 여전히 후속 확인 대상이다.
- 초기 커브는 이전 모션의 주요 포즈를 적은 수의 Euler 키로 옮겼다. 이전 Quaternion 보간과 완전히 같은 궤적은 아니며, 특히 큰 회전은 Animation 창에서 직접 다듬을 수 있다.

- 나머지 이동 구간은 같은 방향으로 움직이는 중간 키의 기울기를 이어주고, 방향을 바꾸거나 멈추는 키는 기울기를 0으로 두었다. 단조 구간의 기울기는 인접 구간의 속도를 이용한 가중 조화평균으로 제한했다.
- 현재 GuardHold는 0.116667초, IaidoDoubleSlash는 사용자가 편집한 0.433333초다. 클립 길이와 사용자가 만든 키 자세를 유지했다.
- 발도 적중 기준이 단축된 클립의 첫 베기 쪽을 가리키고 있어, 씬의 Iaido Impact Progress를 0.5833333 → 23/26 ≈ 0.8846154로 맞췄다. 클립 23프레임(0.383333초), 두 번째 베기 구간 가운데에 해당한다. 드라이버의 실제 판정 시간 및 판정 횟수는 변경하지 않았다.
- Undo에 탄젠트 조정과 적중 기준 조정을 기록했다. 원본 .anim은 Temp/WeaponCurveTuning/20261009_233319에 보관했다. 이 백업은 커밋 대상 에셋이 아니다.

#### 이번 커브로 직접 연습하기

1. Play를 끄고 Player → Player Camera → PlayerWeaponRig를 선택한다.
2. Animation 창에서 Normal1을 선택하고 Preview와 Curves를 켠다.
3. Sword → Position.x만 선택해 다른 축의 선을 잠시 숨긴다. 커브 편집 영역에 마우스를 두고 F로 선택된 키가 보이도록 맞출 수 있다.
4. 0.0525초 키(준비 자세)와 0.233333초 키(베기 끝)를 찾는다.
5. 키를 우클릭해 탄젠트를 Free로 두고, 양쪽을 다르게 조절하려면 Broken으로 분리한다. Weighted를 켜면 핸들 길이로 가속 구간의 길이까지 조절할 수 있다.
6. 준비 키의 오른쪽 핸들을 수평으로 길게 뻗으면 그 자세에서 천천히 출발한다. 끝 키의 왼쪽 핸들을 수평으로 길게 뻗으면 끝 자세에 가까워질 때 천천히 멈춘다. 같은 시간 안에 이동을 마치므로 그 사이 구간은 더 빨라진다.
7. 핸들을 짧게 줄여 조정 전과 비교한다. 키 점 자체를 움직이지 않고도 빠르기가 달라진다.
8. Preview 재생으로 보고, 잘못 조절했다면 Ctrl+Z로 되돌린다. 저장 후 Game 창에서 실제 조작감을 비교한다.

- 가로축은 시간, 세로축은 현재 선택한 속성 값이다. Position.x 커브의 가로축도 시간이며 공간의 X축이 아니다.
- 선의 기울기가 크면 해당 속성의 변화가 빠르다. 수평이면 그 순간 그 축의 속도가 0이다.
- 키를 좌우로 움직이면 시점이 바뀌고, 위아래로 움직이면 자세가 바뀐다. 탄젠트는 키 사이에서 이동하는 속도를 바꾼다.
- 서로 다른 축의 기울기를 바꾸면 전체 3D 궤적도 달라질 수 있다. 한 축만 보고 끝내지 말고 Scene/Game 미리보기를 함께 본다.
- Clamped Auto는 기본적인 부드러움과 과한 돌출 방지에 적합하다. Free/Broken은 준비·타격·복귀처럼 구간의 성격을 직접 구분할 때 적합하다.
- GuardHold와 Rest는 자세 유지용이라 수평 커브가 정상이다. 움직임 학습에는 Normal1 또는 GuardDeflect를 사용한다.

#### 이번 조정 확인 및 남은 연결

- 커브별 모든 원래 키 값/시간 일치, 키 보간 오차 0 확인. 구간당 101개 샘플로 검사했으며 최대 범위 초과는 약 0.000061(회전값의 부동소수점 오차 수준)이었다.
- Normal1과 발도 클립의 시작/적중 부근/끝을 Animation Preview로 확인했다. Normal1 적중 부근의 Game View도 확인했다. Console 오류/경고는 관측되지 않았다.
- 이번 조정 후 전체 Play Mode 전투 회귀 테스트와 실제 키보드/마우스 입력 테스트는 실행하지 않았다.
- 사용자가 바꾼 GuardHold와 기존 GuardDeflect 시작/끝 자세가 서로 다르다. 탄젠트 조정으로 이 키 자세 차이가 사라지지는 않는다. 가드 성공 시 자세 연결을 다듬는 후속 작업이 남아 있다.
