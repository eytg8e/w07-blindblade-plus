### 1인칭 근접 교전 1차 구현

- 기능 설명: 맹인 시야에서 적의 공격 검기를 읽고 우클릭 가드·패링 후 반격하는 1인칭 근접 프로토타입이다. 적의 실물 검 대신 EnemySlash가 공격을 표시한다.
- 동작 조건 및 처리 흐름: GameSceneInitializer와 Player 프리팹의 기존 초기화 구조를 사용한다. InputManager가 좌클릭 공격, 우클릭 유지 가드를 전달한다. HP는 플레이어 100·적 30, 피해 10을 유지한다.
- 구현 상태: 코드·기존 프리팹·사용 중인 Animator Controller 연결 완료. 새 스크립트·씬 오브젝트·애니메이션 클립은 추가하지 않았다. 대각선 내려치기 변경 후 사용자 허용에 따라 Play 세션 1회를 수행했다.

#### 1단계: 기본 베기 2타와 입력 예약

- 좌클릭 일반 공격은 Normal1 → Normal2의 최대 2타 연계다. 현재 기본값에서는 첫 베기 시작 0.22초부터 다음 클릭 하나를 예약하며, 여러 클릭을 누적하지 않는다. 타격 구간 종료 후 0.12초가 지난 0.42초부터 판정이 완료된 첫 베기의 남은 후딜을 끝내고 2타를 시작한다. 두 번째 베기 중에는 세 번째 공격을 예약하지 않는다.
- 두 타 모두 타격 중심 0.22초, 피해 구간 0.14~0.30초, 단독 행동 길이 0.48초다. 연계 시 첫 타의 Recovery는 생략하고 이동 입력을 유지한다. 연계하지 않은 공격 또는 마지막 타 종료 후에는 기존 일반 회복 0.18초가 적용된다.
- 첫 타를 정상 종료한 뒤 0.65초 안에 회복을 마치고 다시 클릭하면 2타를 시작한다. 시간이 지나거나 두 번째 타가 끝나면 다음 자유 상태 공격은 1타다. 피격·가드·충전·사망·일시정지·입력 포커스 상실·공격 취소에서 예약 또는 연계 유지 상태를 정리한다. 준비 중에 클릭했다고 현재 공격을 취소하지 않는다.
- KatanaCombatCoordinator는 예약과 타수를 관리하고 PlayerController.TryChainNormalAttack은 이전 판정 완료·공격 ID를 확인한 뒤 새 ID로 일반 공격을 시작한다. 피해량·사거리·SphereCast·중복 피해 방지 방식은 유지한다. 각 타의 검기와 기존 A/B 스윙 소리는 기존 사건 흐름으로 재생한다. 사용자가 편집한 SwordSlashVFX Transform은 변경하지 않았다.
- KatanaWeaponVisual은 기존 Normal1·Normal2 상태를 사용한다. Responsive 클립의 편집 샘플에서 비정상 위치·정지 보간이 확인되어, 상태 Motion을 정상 샘플이 확인된 PoseAligned/Clips/Normal1.anim·Normal2.anim으로 연결했다. 원본 애니메이션 파일과 기타 상태는 변경하지 않았다. 일반 공격의 적중 진행도는 1타 0.75, 2타 0.4다.
- 일반 타격 구간은 PlayerActionDriver의 Normal Strike Window로 분리했다. 충전 발도의 기존 0.32초 적중·0.60초 동작·0.20초 Strike Window와 가드·패링·맹인 시야·적 공격 규칙은 유지한다.
- Inspector 조정값: Coordinator의 Combo Buffer Window·2타 연계 지연 (초)·Combo Reset Delay, Driver의 Normal Hit Time·Normal Action Duration·Normal Strike Window, Visual의 Normal1/Normal2 Impact Progress다. 2타 연계 지연은 내부 _comboFollowThrough 필드를 유지하며 기본 0.12초다. 첫 타격 종료 이후의 지연이고 값을 키우면 2타가 늦어진다. 첫 동작이 끝날 만큼 길게 설정하면 예약을 유지하고 회복 종료와 지연 시각을 모두 기다린 뒤 2타를 시작한다. 회복 후 새 클릭으로 2타를 예약하는 경우에도 같은 지연을 적용한다.
- 컴파일·Animator Motion 참조·프리팹 설정·편집 모드 클립 샘플을 검증했다. 이번 단계의 실제 연계 조작감과 최종 입력 흐름은 Play 미검증이다. 새 스크립트·씬 객체·테스트 코드는 추가하지 않았다.

#### 2단계: 동일한 적 피격 반응

- 사용자 요청으로 2타의 강한 마무리 개념과 피해 문맥 ComboStrike 및 별도 Finisher 설정을 제거했다. 두 타는 같은 피해 10과 동일한 피격 반응 규칙을 사용하며 HP·사거리·판정 방식은 유지한다. 타수는 모션과 연계 순서에만 사용한다.
- 근접 적 프리팹 3종의 두 타는 경직이 허용될 때 0.16초 경직을 적용하고 0.12초 동안 0.12m 밀림을 적용한다. 밀림은 빠르게 시작해 감속한다. 사망 타격은 추가 이동·경직을 적용하지 않고 기존 피해·사망 이벤트를 유지한다.
- 두 타 모두 이미 경직 중이거나 경직 종료 후 0.45초의 중단 제한 시간에는 경직을 추가하지 않는다. 피해·밀림·타격 피드백은 유지한다. 2타가 제한을 무시하는 특례도 제거했다. EnemyAttackSelector.Stagger는 기존 패링·가드의 남은 회복과 새 경직 중 큰 시간을 보존한다. 풀 반환 시 경직·밀림·중단 제한 상태를 정리한다.
- EnemyMotor의 기존 NavMeshAgent.Move로 수평 밀림을 적용하고 NavMesh Raycast 경계에서 이동량을 제한한다. Rigidbody 힘·NavMesh 재생성·프로젝트 설정 변경은 없다. 실제 밀림 거리는 주변 NavMesh 경계에 따라 줄어들 수 있다. [Unity Move API](https://docs.unity3d.com/kr/current/ScriptReference/AI.NavMeshAgent.Move.html)
- PlayerCombatEffects는 물리 검 접촉 표시와 별도로 실제 적 피해 확정 이벤트를 받아 두 타에 같은 0.25 강도의 짧은 카메라 반동을 적용한다. 논리 조준 방향은 유지한다. 헛스윙·벽 접촉에는 이 반동을 적용하지 않는다. 기존 타격·혈흔·피격음 사건을 재사용하고 별도의 소리나 애니메이션을 추가하지 않았다.
- EnemyHealth의 Hit Recovery·Hit Interrupt Cooldown·Hit Push Distance·Hit Push Duration, PlayerCombatEffects의 Hit Recoil Strength로 튜닝한다. Cancel Attack On Hit가 켜진 적에 피격 경직·밀림을 적용한다. 이번 프로필은 기존 근접 적 3종에 저장했다.
- 컴파일·프리팹 설정·기존 씬의 상속 상태를 검증했다. 실제 밀림·경직의 체감과 경직 제한에 따른 적 반격 빈도는 Play 미검증이다. 테스트 코드를 작성하지 않았다.

#### 공격 규칙

- 플레이어는 부채꼴 대신 실제 칼날 판정 높이에서 회전 박스 기즈모를 표시한다. 현재 OverlapCapsule과 직전·현재 칼날의 다섯 지점 SphereCast 영역을 포함하는 외접 박스다. 구체·캡슐과 박스 모서리는 정확히 같지 않으며 BoxCollider를 피해 판정에 추가하지 않는다. 공격 도중 최근 검사 한 구간만 표시하고 종료 후 Gizmo Duration 동안 유지한다. 초록은 적중, 빨강은 피해 없는 접촉, 청록은 접촉 없는 검사다. 편집 모드 선택 미리보기는 현재 칼날·사거리·두께의 노란 외접 박스다. 기존 누적 궤적과 접촉점 표시는 제거했다. Player 프리팹의 Show Attack Gizmos는 true다.
- 적의 부채꼴 요약은 발 기준 높이 +0.02m에 유지하고, 상세 칼날 박스 표시는 기존 Show Blade Trajectory Gizmos 설정을 따른다. 이번 플레이어 기즈모 변경에서는 적의 설정과 실제 피해 판정을 변경하지 않는다.
- 플레이어 판정은 매 타격 샘플마다 OverlapCapsule 1회와 칼날의 다섯 지점에 대한 SphereCastAll 최대 5회다. 이동 없는 지점은 캐스트를 생략한다. 플레이어의 실제 판정은 변경하지 않았다.
- 적은 전조 시작에 대상이 보는 좌상단→우하단 또는 우상단→좌하단 내려치기를 각각 50% 확률로 선택한다. 선택한 방향은 해당 공격 동안 유지하며 실제 Box Trigger와 EnemySlash가 같은 대각선 궤적을 사용한다. 전조 중에는 시각 효과를 재생하지 않는다. 전조·베기·가드·패링 시간은 유지한다.
- 플레이어 일반 베기는 0.14~0.30초 동안 칼날의 이전·현재 경로를 검사한다. PlayerActionDriver가 시간과 종료를 관리하고 LateUpdate에서 Animator 평가 뒤 칼날을 검사한다. PlayerAttackResolution.IsComplete로 미완료 검사와 최종 적중·빗나감을 구분한다. 동작·연계·회복 시간은 위 1단계 규칙을 따른다.
- 실제 1인칭 칼날 뷰모델 길이는 편집 샘플 기준 약 0.385m이다. EnemyCombatService의 Use View Model Reach를 켜 칼날 방향을 유지하고 Normal Attack Range에 맞춰 월드 칼날 길이를 보정한다. 게임 사거리 기본값은 1.5m, 판정 두께 반경은 0.1m다. 블레이드 참조·사용자 VFX Transform은 유지했다.
- 플레이어 검기와 SwordEffectEmitter도 같은 베기 구간을 사용한다. 칼날 경로·접촉 이펙트·피해는 분리된 책임이며, 피해는 최초 접촉으로 한 번만 확정한다. 물리 Collider·차폐·레이어와 사거리에 따라 실제 적중 시점은 달라진다.
- 적 근접은 전조 0.45초 → 베기 0.24초 → 회복 0.55초다. 적 몸 기준 높이 1.6m, 사거리 2m, 시작 -70도~종료 +70도다. 칼날 크기의 BoxCollider Trigger 하나를 베기 구간에만 활성화하고 FixedUpdate마다 위치·회전을 갱신한다. 두께는 0.24m이며 EnemySlash 및 박스 기즈모가 같은 좌표를 사용한다. 반복 SphereCast와 각도별 세부 검사는 제거했다.
- 세 근접 적 프리팹 내부에 MeleeHitbox 자식을 연결하고 루트에 Kinematic Rigidbody를 추가했다. 중력과 물리 이동은 사용하지 않으며 기존 NavMeshAgent가 이동을 담당한다. OnTriggerEnter/Stay에서 최초 접촉만 처리하고 종료·취소·가드·패링 즉시 판정 박스를 끈다. 대상 접촉 시 차폐 확인용 RaycastAll은 한 번만 수행한다. 플레이어의 기존 칼날 경로 검사는 유지한다.
- Enemy_SingleMelee와 Enemy_DeflectableMelee의 Melee Only를 켰다. 기존 씬에 추가된 돌진 컴포넌트를 삭제하지 않고 첫 프로토타입 교전에서는 근접 패턴만 선택한다. 다른 적 유형·MultiPattern의 돌진·원거리는 이전 계약을 유지한다.
- 공격 시작 쿨다운은 근접 프리팹에서 0.4초이며 실제 준비·베기·회복 동안 재공격할 수 없다. 피격 반응은 위 2단계의 타수별 경직·밀림·중단 제한 규칙을 따른다. 피격이 기존 패링 회복 시간을 단축하지 않도록 남은 회복을 보존한다.

#### 방어와 피드백

- 좌클릭에 자동으로 열리던 패링 창을 제거했다. 우클릭 유지로 가드를 올리고, 가드 시작 직후 0.18초 안에 전방 120도 내 근접 공격이 접촉하면 정확한 패링이다. 일반 가드도 같은 전방 제한을 사용한다. 돌진·투사체·후방 공격은 이 1차 가드로 막지 않는다.
- 정상 가드 또는 패링은 HP 피해를 소비하고 적의 해당 베기를 중단한다. 일반 가드는 최소 0.55초, 패링은 최소 0.9초 회복을 준다. 자동 반격 피해는 없으며 우클릭을 놓고 좌클릭으로 반격한다.
- 일반 가드 뒤 플레이어의 새 공격에는 0.18초 반동 회복 제한이 있다. 정확한 패링은 이 제한 없이 바로 반격할 수 있다. 기본 이동 3.5m/s, 가드 이동 2.2m/s, 웅크리기 1.4m/s로 거리 조절이 가능하도록 프리팹 값을 조정했다.
- KatanaCombatCoordinator.DefenseSucceeded(KatanaDefenseResult)가 원래 피해·실제 플레이어 검에서 계산한 섬광 위치·정확한 패링 여부를 한 번 전달한다. PlayerCombatAudio와 PlayerCombatEffects가 이 이벤트를 받아 기존 SwordHit 사운드와 SwordClash 프리팹(GuardClash ID 5)을 재생한다.
- KatanaWeaponVisual은 GuardEnter·GuardHold·GuardDeflect를 사용한다. 기존 비활성 리그의 클립을 현재 KatanaV2_Responsive.controller에 연결했으며 새 클립은 만들지 않았다.
- PlayerMotor가 시점·웅크리기 위치에 짧은 카메라 반동을 합성한다. ViewForward/ViewOrigin은 반동 없는 논리 시점으로 유지하여 화면 흔들림이 조준과 방어 방향을 바꾸지 않는다.
- 실제 피격에는 카메라 반동과 0.18초 플레이어 회복이 있다. 진행 중인 일반 공격을 중단하고 추가 피해 검사를 닫는다. HP 0의 게임오버 계약은 유지한다.

#### EnemySlash와 시야

- 최종 사용자 지시에 따라 굵은 LineRenderer·TrailRenderer와 EnemySlashBlade 재질을 제거했다. Resources/Prefabs/Effects/EnemySlash의 원래 ParticleSystem 6개·텍스처·내부 회전을 사용한다. 전조의 시각 표시는 없다. 피해는 별도 BoxCollider만 담당한다.
- Enemy_SingleMelee·Enemy_DeflectableMelee·Enemy_MultiPattern 프리팹의 자식 SlashEffect_UpperLeft·SlashEffect_UpperRight에 EnemySlash를 중첩 프리팹으로 연결했다. 이름은 적을 마주 보는 플레이어 기준의 시작 방향이다. 각 자식의 Transform Position·Rotation·Scale을 Prefab Mode Inspector에서 직접 편집한다. EnemyCombatEffects의 Upper Left Slash·Upper Right Slash 슬롯은 각 자식 루트 ParticleSystem이다. 기존 씬 컴포넌트의 슬롯이 비어 있으면 같은 이름의 프리팹 자식을 찾아 연결한다.
- EnemyCombatEffects는 실제 AttackCommitted에서 선택된 방향의 자식만 활성화·재생한다. 코드에서 Transform을 변경하거나 카메라를 향하도록 자동 보정하지 않는다. Local 시뮬레이션 파티클은 적과 함께 이동한다. 원본 Slash17·Slash16·A35에서 만든 EnemySlash 전용 재질의 강화된 농도와 원본 텍스처·색조·소멸 곡선을 유지한다.
- 실제 방출 시간·Burst·입자 수명을 합산한 원본 표시 시간을 베기 0.24초에 맞춰 simulationSpeed만 보정한다. 공격당 한 번 재생하고 공격 종료 시 방출을 중단하며 최대 0.15초 잔광 후 비활성화한다. 취소·적 비활성화는 즉시 정리하고 원래 속도를 복원한다. 근접 검기를 런타임 생성·풀링하는 전용 추적 API는 제거했다. 기타 공격의 기존 EffectManager.Play는 유지한다.
- Melee Only 모드에서는 기존 돌진용 걷기 금지 설정이 있어도 플레이어에게 접근한다. 중복 씬 override는 첫 표현 컴포넌트만 실행한다.
- 일반 시야 옵션과 Play 모드 Outline 비활성화 분기를 제거했다. MainMapSession은 SensoryPerceptionMask를 활성화하고 감각 효과를 표시한다. ScreenSpaceOutlineFeature는 원래 감각 마스크 기반 패스를 계속 실행한다. TerrainMemory는 기존 Use Terrain Memory 설정을 따른다. URP 프로젝트 설정·렌더러 에셋은 수정하지 않았다.

#### 연결 및 협업

- 기존 Player·적·EnemySlash·SwordClash·Initializer 프리팹을 수정한다. 씬 파일이나 사용자 배치를 덮어쓰지 않는다. 단일 피해·방어 결정 후 표현이 따라가는 구조를 유지한다.
- 팀원이 새 공격을 추가할 때 실제 칼날 GetBladePose와 피해 구간을 먼저 정의하고 표현·기즈모에 같은 값을 전달해야 한다. 사운드는 기존 SwordHit 이벤트를 재사용했다. 별도 방어 전용 FMOD 이벤트는 추가하지 않았다.
- 직접 조정할 값은 PlayerActionDriver의 타격 시간·동작 길이·Strike Window, EnemyMeleeAttack의 사거리·높이·두께·베기 각도·전조·회복, Coordinator의 Parry Window, PlayerMotor의 Recoil Return Speed다.
- 현재 가드는 방향·시간 기반 방어 영역이다. 실제 두 검 Mesh Collider 사이의 물리 충돌, 스태미나, 적 가드 AI, 다방향 공격, 돌진·원거리의 추가 방어 규칙은 1차 범위에 포함하지 않는다.

#### 검증과 한계

- Unity C# 컴파일 성공. 현재 사용 중인 Animator에 방어 상태 3개와 기존 Motion·ActionProgress 연결을 확인했다. 편집 모드 클립 샘플로 실제 칼날 뷰모델 길이와 가드 위치를 확인했다.
- CombatTest와 맵 3개를 PreviewScene으로 읽어 일반 시야 설정, 플레이어 타격 시간, 칼날 참조, 적 근접 프로필 및 누락 스크립트 0개를 확인했다. 기존 씬 루트 수와 미저장 상태는 유지했다.
- 2026-10-11 대각선 변경 후 CombatTest에서 Play 세션 1회: 기존 적을 런타임에 플레이어 전방 1.5m로 이동해 교전을 확인했다. 양쪽 전조 방향의 무작위 선택, OnTriggerEnter를 통한 공격당 피해 10, 일반 가드의 HP 유지와 0.55초 회복, 정확한 패링의 HP 유지와 0.9초 회복, 회복 중 Trigger 비활성화를 확인했다. 기존 방어 API로 가드 입력을 전달했으며 실제 마우스 조작 검증은 아니다. 당시의 선 표시와 방어 섬광을 Game 화면 캡처에서 확인했다. 이후 사용자 요청으로 원본 파티클 표현으로 교체했으므로 이 Play 결과는 최종 파티클 표시를 검증하지 않는다. 씬 배치와 저장 상태는 유지했다.
- 최종 원본 파티클 변경은 컴파일·프리팹 참조·원본 방출 시간으로 검증했다. 편집 PreviewScene의 임시 카메라 렌더는 기존 렌더러 윤곽선 패스의 영향을 받아 최종 아트 시인성을 검증하지 못했다. 추가 Play 진입은 수행하지 않았다.
- 표시 각도·전용 재질 농도·부채꼴 기즈모 변경도 컴파일과 프리팹 설정으로 확인했다. 최종 게임 화면에서의 농도와 기울기 체감은 미확인이다.
- 맹인 시야 복구·프리팹 자식 검기 변경은 컴파일과 근접 프리팹 3종·기존 씬 4개의 자식 및 연결 경로로 검증했다. Transform 자동 변경 코드와 Outline 비활성화 분기가 제거된 것을 확인했다. 추가 Play 테스트는 수행하지 않았다. 사용자가 직접 편집한 검기 방향과 실제 Collider의 일치는 자동 보정하지 않는다.
- 최초 Play 초기화 중 도구 호출 1회가 메인 스레드 시간 초과로 실패했으나 같은 세션에서 연결이 복구됐다. 추가 Play 진입은 하지 않았다. 효과음 청취·카메라 반동의 체감·전 구간 이동 중 시인성은 미확인이다. Trigger는 현재 물리 간격 0.02초의 이산 판정이므로 매우 빠른 이동에서 접촉 누락 여부는 추가 검증이 필요하다. 테스트 스크립트는 작성하지 않았다.
