### 게임 공통 구조 검증 씬

- 기능 설명: PLAN_0005의 현재 플레이어 접근점, 입력 정책, 상태/UI 책임 분리, 초기화 수명 및 플레이어 내부 전투 서비스를 기존 컴포넌트로 재현하는 수동 검증 씬이다.
- 동작 조건 및 처리 흐름: Assets/Scenes/GameArchitectureValidation.unity를 단독으로 열어 Play한다. 생산용 Player와 GameSceneInitializer를 사용하며 _showGameplayControls 설정으로 GameplayControlsUI를 UIManager가 ResourceManager에서 동적 생성하여 현재 InputManager 및 GameStateManager에 연결한다.
- 구현 상태: 씬·독립 조작 UI·NavMesh·안내 작성 및 Play 검증 완료. 자동 테스트 코드는 추가하지 않았다.

| 파일 경로 | 클래스 / 메서드 | 역할 |
| --- | --- | --- |

#### 연결 및 협업

- 연결된 기능: [게임 씬 공통 구성](게임_씬_공통_구성.md), 플레이어 입력·전투, 복도 패배 판정, 지형 기억.
- 공유하는 코드 및 상태: 생산용 컴포넌트와 프리팹을 재사용한다. 매니저는 생산용과 동일하게 Game에서 개별 동적 생성되며 조작 화면만 추가로 구성한다.
- 씬별 설정: 기억 범위는 X/Z -12~12m, 시작 위치는 (0, 0.1, -6), 적 위치는 (6, 0, 6), 감지 반경은 5m이다. 적의 순찰은 씬에서만 비활성화했다.
- 테스트 전용 차이: 커서를 잠그지 않아 화면 우측 버튼을 클릭할 수 있다. 기존 적 Placeholder 렌더러는 이 씬에서만 켜서 적 위치를 확인한다. 카메라에는 FMOD StudioListener를 연결했다. 바닥 표식은 렌더링용이며 추가 Collider가 없다.
- 중복 또는 충돌 사항: 기존 미저장 StraightCorridor와 생산용 코드·프리팹은 수정하지 않았다. 테스트 씬은 다른 플레이어 씬과 함께 Play하지 않는다.
- 승인 필요 사항 및 결과: 사용자가 변경 사항과 의도를 검증할 테스트 씬 제작을 요청했다. 기존 A 모드를 유지했다. dev 브랜치에서 Git CLI와 커밋은 수행하지 않았다.

#### 조작과 검증 의도

WASD 이동, 마우스 시점, 좌클릭 공격, Ctrl 차지, 우클릭 쳐내기를 사용한다. 오른쪽 검증 패널의 입력 차단·허용 버튼은 Playing 상태에서 수동 입력 정책을 확인하는 용도다. 게임오버 후에는 재시작으로 플레이 상태를 복구한다. 수동 허용 버튼은 입력 API를 직접 호출하므로 게임오버 상태의 정상 복구 절차를 대신하지 않는다.

| 절차 | 기대 결과 | 확인하는 의도 |
| --- | --- | --- |
| 씬 단독 Play | 플레이어가 하나이며 Game 하위 입력·상태·UI 매니저는 각각 하나, 화면은 UIManager 하위 공통 Canvas 하위, 기억은 Initializer 하위에 생성 | 씬 공통 객체를 분산 배치하지 않고 Initializer가 준비 |
| Ctrl 차지 후 입력 차단 | 차지가 종료되고 이동·시점·공격 명령이 차단되며 버튼은 계속 조작 가능 | 입력 허용 정책의 소유자는 InputManager, UI 입력과 구분 |
| 입력 허용 | 이동·시점·공격이 다시 가능 | 어댑터를 비활성화하지 않고 명령 전달을 관리 |
| 게임오버 버튼 | 플레이어 Dead, 시간 정지, 게임오버 패널과 RESTART 선택 | 상태 결정은 GameStateManager, 화면 표시는 UIManager |
| NOT YET | 게임오버 상태와 화면 유지 | 게임플레이를 복구하지 않는 UI 선택 |
| RESTART 또는 검증 패널 재시작 | 같은 테스트 씬 재로드, 입력 복구, 새 플레이어와 서비스 하나 | 이전 플레이어 참조·서비스·시간 상태가 남지 않음 |
| 적에게 접근해 먼저 공격받기 | 첫 적중 전 피격으로 게임오버 | 라운드 판정이 상태 매니저에 요청하고 입력/UI를 직접 제어하지 않음 |
| 재시작 후 적 먼저 공격하기 | 기존 적에게 피해 및 사망 적용 | 씬 루트 전투 서비스 없이 플레이어 내부 서비스가 판정 |
| 바닥 표식 사이 이동 후 멀어지기 | 방문 범위의 기억 윤곽선 유지 | TerrainMemory가 현재 플레이어 위치를 사용 |
| 재시작 | 이전에 방문한 먼 영역의 기억 초기화 | 기억은 영속 Game이 아닌 씬 수명을 따름 |

#### 현재 플레이어와 매니저 접근점 확인

기존 Unity CLI를 프로젝트 루트에서 사용하면 실행 중 공개 상태를 읽을 수 있다. 아래는 스크립트 파일을 만들지 않는 조회 명령이다.

```sh
unity command --project-path "$PWD" eval 'return new { player = Game.Player.name, scene = Game.Player.gameObject.scene.path, state = Game.Instance.GameStateManager.State.ToString(), input = Game.Instance.InputManager.IsGameplayInputEnabled, services = UnityEngine.Object.FindObjectsByType<GameStateManager>(UnityEngine.FindObjectsSortMode.None).Length };'
```

Play 직후에는 테스트 씬 경로, Playing, input=true, services=1이 기대값이다. 게임오버 후에는 GameOver와 input=false, 재시작 후에는 다시 Playing과 services=1이어야 한다.

#### 실제 검증 결과

- 누락 스크립트 0개, 버튼 4개에 각각 현재 서비스 인스턴스를 대상으로 하는 persistent listener 1개, 적 NavMeshAgent.isOnNavMesh=true를 확인했다.
- 테스트 씬의 실제 버튼 onClick을 호출해 입력 차단 시 차지 종료, 입력 허용, 게임오버 입력 차단·시간 배율 0·게임오버 패널 표시를 확인했다.
- 재시작 버튼 호출 후 Playing·input=true·시간 배율 1·상태 서비스 1개와 새 플레이어 인스턴스를 확인했다.
- CharacterController 이동으로 기억 픽셀 수 8,920→16,166 증가를 확인했고 재시작 후 8,920으로 돌아오는 것을 확인했다.
- 기존 DamageReceiver API로 적 피해를 전달해 첫 적중 전 피격이 게임오버로 연결됨을 확인했다. 플레이어 내부 전투 판정 API로 적 HP 30→0 및 HitConfirmed=true를 확인했다.
- Game View 캡처로 한국어 안내와 버튼이 잘리지 않고, FMOD 디버그 표시와 겹치지 않으며 바닥·기둥 윤곽선이 보이는 것을 확인했다.
- 실제 키보드·마우스 조작에 의한 전체 이동·쳐내기·접근 교전은 미확인이다. 버튼 검증은 실제 onClick 호출이며 포인터 클릭 자동화는 수행하지 않았다.
- 다른 Unity 인스턴스와의 FMOD 포트 충돌 경고가 있었다. 씬 로드 중 도구 요청 타임아웃은 재접속 후 씬·상태를 확인했으며 게임플레이 예외로 간주하지 않는다.
- 검증 후 원래 열린 StraightCorridor(미저장)와 Stairwell(저장됨)을 복원했다. 런타임 검증의 피해·이동·상태는 씬에 저장하지 않았다.


#### 개별 매니저 및 UI 접근 검증

- GameplayServicesValidation Variant를 제거하고 GameplayControlsUI 독립 프리팹으로 교체했다. 버튼은 화면 초기화 시 현재 매니저에 연결되고 정리 시 해제된다.
- UIManager.Get<GameplayControlsUI>(), Show<GameplayControlsUI>(), Hide<GameplayControlsUI>()로 동일 화면 인스턴스를 조회하고 표시를 제어한다.
- 입력 허용 버튼은 Playing에서만 작동하므로 게임오버 중에는 입력 차단을 유지한다.

- 최종 Play 검증에서 제네릭 조회가 같은 화면을 반환하고 Hide/Show가 표시를 변경함을 확인했다. 게임오버 화면 자체의 상태 구독으로 GameOver 표시·입력 차단이 유지됐으며 재시작 후 Playing·시간 배율 1·입력 허용·UIManager 및 GameStateManager 각각 1개를 확인했다.
- 변경된 공통 프리팹 3개의 누락 스크립트 0개와 Unity 컴파일 오류 0건을 확인했다. 실제 포인터·키보드 조작은 추가 검증하지 않았다.

- UI 리소스 동적 로드 전환 후 같은 타입 반복 조회가 인스턴스를 재사용하고 기존 조작 버튼 및 재시작 동작이 유지됨을 Play API로 확인했다. UI 프리팹 인스펙터 연결은 필요하지 않다.

- Game의 매니저 동적 로드 이후 StraightCorridor에서 검증 씬으로 전환하고 재시작해도 입력·상태·UI 매니저의 인스턴스가 재사용됨을 확인했다. Initializer/어댑터 비활성화 시 정책 구독은 제거되고 재활성화 시 1개로 복구된다. SceneServicesChanged 없이 명시적 Initialize/Shutdown과 입력 정책 이벤트만 사용한다.

- 공통 Canvas 전환 후 Canvas·Scaler·Raycaster 각각 1개, 게임오버와 검증 패널 배치 및 기존 버튼·재시작 동작을 확인했다. 기준 해상도는 1920×1080이고 검증 패널의 기존 화면 크기와 여백은 보정해 유지했다.
