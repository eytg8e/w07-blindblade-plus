### 메인맵

- 기능 설명: 맹인검사가 어두운 폐사찰에서 적의 발자국과 파동을 읽으며 이동하는 첫 메인맵이다.
- 동작 조건 및 처리 흐름: MainMap 씬에서 플레이어 입력, 기존 적 프리팹, 공통 Game 감각 매니저를 연결한다. 진입로, 꺾인 회랑, 중정, 마지막 마당을 순서대로 통과한다.
- 구현 상태: MainMap.unity, 전용 재질, NavMesh 에셋 생성 완료. Unity에서 메인맵 플레이와 적 인스턴스 5개를 확인했다. 최신 플레이어 검 표현 누락 수정 후 검 4개 파트 표시와 가드 포즈 전환, 해제 후 기본 포즈 복귀 및 일반 공격 시작을 확인했다. 제작기 코드의 Unity 로드와 실행을 확인했으며 전체 맵의 주행·교전 검증은 미확인이다. 진행 모드 A 승인. 전투·청각 계약 신규 어댑터는 별도 승인 대기.

#### 연결 및 협업

- 연결된 기능: PlayerController, PlayerMotor, KatanaInputCommandAdapter, FootstepEmitter, EnemyController, EnemyPatrol, Game.SensoryManager, Managers.Sound.
- 공유하는 코드 및 상태: 플레이어 Transform을 SensoryManager.SetObserver에 등록한다. 적의 EnemySensor.Target은 씬 플레이어로 지정한다. 공통 FootstepEmitter는 지면 접촉 위치로 기존 감각 효과를 요청한다.
- 실제 연결 시점: GameSceneInitializer가 Game 세션과 플레이어 전투 서비스를 준비한 뒤 SensoryManager.SetObserver(_player.transform)을 호출하고, PlayerController.FootstepEmitted를 구독한다. HandlePlayerFootstep은 PlayerFootstepEvent.NoiseStrength를 사용해 플레이어에 발소리를 재생한다. 비활성화 시 구독을 해제하고 감각·사운드 설정을 정리한다.
- 플레이어 구성: 공유 Player.prefab을 사용한다. 입력은 KatanaInputCommandAdapter, 검 표현은 KatanaWeaponVisual, 판정 타이밍은 PlayerActionDriver, PlayerController와 PlayerMotor가 상태·이동을 담당한다. 현재 씬에는 샌드박스 전용 테스트 구성 요소가 없다.
- 플레이어 가져오기 수정: 공유 Player.prefab으로 전환하면서 씬의 플레이어 인스턴스 참조와 적 Target 연결을 보존했다. Controller의 Motor/ViewCamera, Motor의 CharacterController/CameraPivot 및 입력·검 표현 컴포넌트의 플레이어 참조는 프리팹 연결을 사용한다.
- 제작 도구 정리: 사용자 요청으로 일회성 BuildMainMap.cs와 해당 meta를 제거했다. 생성 예약 파일은 이미 없어 추가 삭제하지 않았다. 완성된 MainMap 씬·재질·NavMesh와 기존 캐릭터·감각 연결을 사용하며 맵 생성 메뉴나 자동 생성은 사용하지 않는다. 씬은 제작 도구를 런타임 컴포넌트로 참조하지 않는다.
- 팀원 연결 작업: 적 소유 EnemyCombatService가 IPlayerCombatService를 구현하고 PlayerController의 Combat Service Source에 연결되어 있다. 감지 담당은 IPlayerPerceptionProvider를 해당 Source에 연결해야 한다. 적 HP·피격·사망은 EnemyHealth가 처리하고 적 공격은 플레이어 DamageReceiver 경로로 전달한다. 플레이어 체력·사망과 승리 조건은 아직 연결하지 않는다.
- 중복 또는 충돌 사항: 기존 팀 코드·테스트 씬·프로젝트 전역 설정은 수정하지 않는다. 새 씬의 지형만 NavMesh 수집 대상이다. 현재 열린 씬의 미저장 변경은 보존한다.
- 승인 필요 사항 및 결과: 맵 제작 A 승인. 이후 사용자가 B 설계 설명 후 2번 메인 씬 전투 연결 및 모든 적 한 대 사망을 승인했다. 적 소유 EnemyCombatService를 기존 플레이어 계약에 연결하며 플레이어 코드는 수정하지 않는다. 청각 계약 어댑터는 이번 승인 범위에 포함하지 않는다.

#### 설계 및 조정

- 전체 부지는 폭 44m, 길이 72m이며 바닥 높이는 0m로 통일한다. 추락·점프·경사 시스템 없이 기존 이동을 활용한다. 발도 대시 코드는 남아 있지만 기본 입력과 설정에서는 비활성화되어 있다.
- 좁은 회랑에서 한 방향의 발걸음을 읽고 중정에서 여러 방향을 구별한 뒤 마지막 마당의 박자 돌진을 피하도록 구성한다.
- 어둠, 차가운 저강도 조명, 드문 등롱으로 지형 윤곽을 제공하며 기존 발자국·파동·순간 빛이 주요 움직임 단서다. 완전 암전이나 별도 감각 렌더링은 추가하지 않는다.
- 기존 적은 시야 기반 AI다. 소리를 듣고 플레이어를 추적하는 적 AI로 변경하지 않는다.
- 선택한 설계: 평면 마당과 꺾인 회랑은 기존 CharacterController와 NavMeshAgent를 활용한다. 다층 지형은 높이 이동·낙하 처리 범위를 늘리고 완전 암전은 별도 환경 감각 표현을 요구하므로 이번 범위에 넣지 않았다.
- 조정 위치: 새 씬의 EnemyPatrol.Distance는 발자국 경로 길이, EnemySensor.DetectionRange는 교전 시작 거리, LanternLight의 Intensity/Range는 보이는 지형 범위를 바꾼다. NavMeshSurface는 01_World_NavMesh의 자식 Physics Colliders만 수집하며 지형 수정 후 다시 Bake해야 한다.
- 검증 한계: 실제 모델·Animator 대신 기존 임시 검 표현과 ActionDriver를 사용한다. 검 표시·가드 포즈와 행동 콜백 검증은 실제 적중·체력·사망 연결 성공을 의미하지 않는다. MainMap 실행 시 별도로 단독 열어야 한다.

#### 적 전투 연결 갱신

- 적 원본 프리팹 4종을 수정하여 메인 씬의 Connected 인스턴스 5개에 EnemyHealth를 상속한다. 씬 적을 Unpack·교체하거나 배치를 변경하지 않는다. 두 돌진 적은 프리팹의 EnemyChargeHitbox도 상속한다. 사용자 요청으로 모든 적은 양수 피해 한 번에 사망한다.
- 새 EnemyCombatService 루트와 기존 플레이어의 Combat Service Source 참조를 연결했다. 실제 적중 요청은 IPlayerCombatService를 통해 EnemyHealth에 전달한다.
- 플레이어 HP·피격 가드·사망과 청각 자동 타겟 감지는 추가하지 않는다. 기존 Perception·Map Source는 null 그대로다. 발도 공격 판정은 제공하지만 청각 기반 자동 타겟은 실제 IPlayerPerceptionProvider 연결을 기다린다. 상세 계약은 [적 전투 및 체력](적_전투_체력.md)을 따른다.
- 편집 상태에서 누락 스크립트 0개, 적 5개 Collider 참조, 플레이어 전투 Source 및 기존 베이크 데이터를 확인했다. Play 실행 및 실제 교전은 이번 변경에서 검증하지 않았다.

#### 플레이어 피격 연결 갱신

- 2026-10-09 현재 저장된 씬과 런타임 확인에서 플레이어의 기존 DamageReceiver 및 FootstepEmitter는 없었다. 이전 문서의 유지 기록과 다르며 현재 연결 상태를 기준으로 판단한다.
- 플레이어 루트에 DamageReceiver를 상속한 PlayerHealth를 하나 추가하고 MainMap을 저장했다. Max Health는 100이며 가드 중 피해 차단, 실제 피해 HP 감소, HP 0에서 PlayerController.SetDead를 연결했다. 상세 이벤트와 검증 결과는 [플레이어 피격 및 체력](플레이어_피격_체력.md)을 따른다.
- 기존 일반 공격으로 적 HP 30 → 0 및 비활성화를 확인했고, 새 수신자에 실제 근접 공격을 연결해 HP 100 → 90 및 가드 시 HP 유지도 확인했다. 적·플레이어 배치 변경과 AI 고정은 검증 중 런타임에만 적용하고 저장하지 않는다.
- 이번에는 FootstepEmitter, 청각 자동 타겟, 맵 파괴, UI·승패·부활을 추가하지 않았다. 기존 입력·전투 서비스·검 표현·감각 및 NavMesh 설정을 유지한다.


#### 게임 씬 공통 구성 전환 (2026-10-10)

- MainMap은 Player.prefab에 연결하고 EnemyCombatService를 플레이어 내부로 이동했다. GameSceneInitializer가 공통 세션·입력·상태·UI·지형 기억을 초기화한다. 기존 플레이어 구성 차이와 외부 참조는 Override로 보존했다. 지형 기억의 기존 어두운 색상은 공통 TerrainMemory의 MainMap Variant에서 유지한다. 기존 적 프리팹 GUID 누락으로 실제 교전 검증은 제한된다.
- 상세 계약과 검증 결과는 [게임 씬 공통 구성](게임_씬_공통_구성.md)을 따른다.
