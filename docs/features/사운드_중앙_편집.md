### 사운드 중앙 편집

- 기능 설명: 플레이어 전투 상황별 음원·음량·pitch·FMOD Label·재생 시간 보정을 하나의 편집 창에서 관리한다. 공통 음원 Library와 적 준비·베기 자연 종료 설정도 같은 창에서 편집한다.
- 동작 조건 및 처리 흐름: PlayerCombatAudio가 Resources/Sound/CombatSoundProfile을 로드한다. 기존 PlayerController·KatanaCombatCoordinator·피해·접촉 사건으로 상황을 선택하고 예약한다. SoundManager는 기존 재생 API와 새 PlayCombatCue를 함께 제공한다.
- 구현 상태: 플레이어 1·2·3타, 패링 반격, 충전 발도 베기, 시작·일반 공격·충전 공격·패링 발도, 접촉, 가드, 패링, 플레이어 피격의 13개 상황을 등록했다. 기존 베기 시간과 A/B/C 선택, 발걸음 이벤트·음원·음량을 유지한다. 신규 상황의 게임 사건 연결에는 코드가 필요하며 등록된 상황에는 항목을 추가해 여러 음원을 재생할 수 있다.

#### 협업 및 연결

- PlayerController, PlayerActionDriver, KatanaCombatCoordinator, EnemyAttackBehaviour, EnemyFootsteps, 체력·이동·발자국 스크립트와 씬·프리팹·애니메이션은 수정하지 않았다. 기존 공개 사건과 시간 조회 API를 사용한다.
- 기존 SoundManager API는 유지한다. 프로필이 없으면 플레이어의 기존 Inspector 설정을 사용한다. 프로필이 있으면 등록하지 않았거나 비활성화한 상황은 재생하지 않는다.
- 중앙 창의 공통 Library 영역은 기존 사운드 ID와 이벤트 연결을 그대로 편집한다. 적 행동별 ID 선택과 적의 재생 시점은 기존 EnemySoundSettings·공격 코드에 남아 있으며 이번 단계에서 옮기지 않았다.
- 단발 이벤트만 사용한다. 직접 이벤트를 지정해도 기본 SoundId의 이동 허용·Combat Cue·공간 보정 정책을 따른다.

#### 편집 및 청취 순서

1. Unity 메뉴의 BlindBlade/사운드 편집을 연다.
2. 해당 상황을 펼쳐 SoundId 또는 직접 FMOD 이벤트, 음량, pitch, 파라미터 이름·Label을 편집한다.
3. 베기 시간 보정은 기존 베기 구간 시작에 더한다. 음수는 앞당김이며 행동 시작 이전은 0초로 제한한다. 발도·접촉·피격은 사건 이후 양수 지연만 적용한다. 음원 자체의 무음 구간은 FMOD에서 조정한다.
4. 변경한 타이밍은 다음 행동 예약부터 적용한다. 미리 듣기는 음원·pitch·Label을 확인하며 행동 시간·게임 공간 믹싱을 재현하지 않는다.
5. 상황에 음원 추가로 같은 상황의 다른 음원을 겹쳐 재생할 수 있다. 새 항목은 비활성으로 추가된다. 마지막 항목을 삭제하면 해당 상황은 무음이다.
6. Play 후 실제 재생 기록에서 상황·이벤트·발음체·Label·음량을 확인한다. 편집 중 변경은 설정 저장으로 이 두 사운드 에셋만 저장한다. 다른 씬·에셋은 저장하지 않는다.

#### 피드백 반영 (2026-10-11)

- 발도음: 시작 발도와 일반·충전·패링 발도를 별도로 편집한다. 기본 지연은 기존 0초를 유지하며 사용자의 모션 청취로 조정한다. 사건 발생 이전의 발도음은 현재 연결로 지원하지 않는다.
- 접촉·가드·패링: 임시 Combat/SwordHit.wav 대신 기존 Sword/SWORD Hit Metal 02.wav를 사용한 event:/SwordClash와 event:/ParryClash를 Combat Bank에 추가했다. 가드는 기존 pitch 0.85, 패링은 1.25와 음량 1.1을 유지한다. 최종 음색·음량은 청취 미확인이다.
- 적 공격음: EnemyAttackPrepare와 EnemySwordSwing에 Finish Naturally를 켰다. 해당 ID의 개별 StopFor 요청은 음원을 중단하지 않는다. 공격 취소에도 꼬리가 남으며 소유자 전체 정지·비활성화·전체 효과음 정리는 유지한다. 이 정책을 중앙 창에서 끌 수 있다.
- FMOD의 기존 음원 압축·스트리밍 경로 충돌 경고로 첫 Bank 빌드가 거부됐다. 기존 경로 설정을 변경하지 않고 경고 허용 옵션으로 Desktop Combat 및 Master strings 빌드를 완료했다. 기존 TemporarySwordHit 이벤트는 보존했다.

#### 검증

- Unity 6000.0.55f1에서 새 스크립트 컴파일 완료 및 프로필 13개 항목 로드를 확인했다.
- 중앙 창 미리 듣기에서 event:/SwordClash의 인스턴스 생성, volume 0.8, pitch 0.85 및 STARTING을 확인했다.
- 실제 RequestNormalAttack 경로에서 발도 예약과 FirstSlash / SwingType C의 각 1회 재생을 확인했다. 런타임 복제 프로필의 발도 지연을 사용해 원본 에셋을 변경하지 않고 예약을 점검했다.
- 적 스윙은 개별 정지 전후 STARTING이 유지되고 소유자 전체 정지에는 STOPPING이 됐다.
- 실제 RequestNormalAttack → CancelNormalAttack 경로에서 발도·스윙 예약 2개가 모두 제거됨을 확인했다. ID가 유지된 채 상태만 바뀌는 취소도 처리한다.
- 최종 Unity 재컴파일 성공, compilationFailed=false 및 Console 오류 0개를 확인했다. git diff --check를 통과했다. Bank 빌드 캐시는 변경 목록에서 제외하고 기존 폰트 에셋 수정은 보존했다.
- 검증 세션에서 Unity Editor의 t.GetParent assertion 및 FMOD Live Update 9264 포트 점유·일시정지된 시스템 종료 경고를 관찰했다. 최종 Console에는 FMOD 경고 3개가 남았으며 이번 기능에서 프로젝트·FMOD 포트 설정이나 플러그인을 수정하지 않았다. 런타임 재생 요청과 새 이벤트 조회는 성공했다.
- 백그라운드 Unity에서는 게임 시간이 진행되지 않아 프레임 Step으로 실행했다. 실제 스피커 청취·발도 최종 타이밍·다수 적에서 음원 꼬리 겹침은 미확인이다. 테스트 스크립트는 작성하지 않았다.
