#### 사용 방법

1. Assets/Scenes/KatanaCombatPreview.unity를 연다. 원본 MainMap은 새 전투 버전으로 전환하지 않았다.
2. 게임 창을 한 번 클릭해 커서를 잠근다. 이 첫 클릭은 공격·쳐내기에 사용하지 않는다.
3. WASD 이동, 마우스 시점, 좌클릭 일반 공격, 왼쪽 Ctrl 충전 유지, 충전 완료 중 좌클릭 발도, 우클릭 최초 누름 쳐내기, Esc 커서 해제.
4. 일반 공격의 베기와 Recovery 동안 들어온 추가 공격은 무시한다. Recovery가 끝나고 0.6초 안에 다시 누르면 Normal2가 된다. 입력을 미리 저장하지 않는다.
5. 쳐내기는 실제 근접 타격 직전 우클릭을 눌러야 한다. 원거리·돌진·후방 타격은 이번 버전의 쳐내기 대상이 아니다.
6. 피격이 전달되면 HUD의 Incoming damage forwarded와 Console 로그로 확인한다. 이 씬에 플레이어 HP 기능을 추가하지 않았으므로 체력 감소·사망은 별도 수신 시스템이 연결해야 한다.
7. 이번 씬에는 기존 F8 가드 검사 기능을 연결하지 않는다. 실제 적의 공격을 사용한다.

#### 상태 전환과 설계 이유

전투 행동과 검의 물리적 자세를 구분한다. `PlayerController.CurrentState`는 기존 상태이고, `KatanaWeaponState`는 Sheathed / Drawn / Sheathing이다. 쳐내기 시도와 성공 동작은 Coordinator가 별도로 소유한다.

- 일반 공격: 납도 → Normal1 → 0.25초 Recovery → 발도 대기 → Normal2 또는 자동 납도.
- Normal2 종료: 납도 표현 시작 + 기존 Recovery. 납도 때문에 별도 후딜을 추가하지 않는다.
- 충전: 납도 대기에서 검과 칼집 전체를 함께 움직인다. 이미 발도된 경우 ChargeFromDrawn의 앞부분에서 먼저 납도한다. 기존 충전 시계는 그대로 진행한다.
- 충전 취소: ChargeRelease로 납도 대기 복귀. 다시 검을 뽑지 않는다.
- 강공격: 기존 대시 → Double Slash → 마지막 베기 판정 1회 → 기존 결과별 Recovery. 베기 종료 후 납도한다.
- 쳐내기: 우클릭 시도 → 타격이 짧은 창 안에 도착하면 성공 → Normal1/2를 표현만 재생 → 대기 또는 납도.
- 실패한 쳐내기는 베기를 실행하지 않는다. 시도 중 검 리그를 0.1초 동안 조금 들어 올리는 표현만 있다.
- 일반 공격과 쳐내기는 성공 순번을 공유하지 않는다. 종류를 바꾸면 다음 성공은 1타다. 실패 시도는 성공 횟수를 증가시키지 않는다.
- 일시정지는 기존 Controller를 통해 전달하며 카타나의 시계도 멈춘다. 사망 이벤트는 쳐내기와 연계를 취소한다.

선택 이유: 기존 PlayerController가 sealed이며 이동·발소리·맵 연결이 이 타입을 사용한다. 이를 통째로 복제하면 Relay·입력·팀 참조까지 복제가 늘어난다. 따라서 명령 창구를 앞에 추가하는 합성(composition)을 사용했다. Animator가 판정까지 소유하는 방식으로 바꾸면 기존 드라이버와 중복 판정 위험이 있으므로 이번에는 유지했다.

주의: 쳐내기 성공 표현 중 기존 PlayerController 상태는 Free일 수 있다. 신규 게임 입력 시스템은 반드시 Coordinator의 명령과 CanStartAction을 사용해야 한다. 기존 Controller를 직접 호출하면 카타나 명령 제한을 우회한다.

#### Unity / C# 학습 포인트

1. **합성**: KatanaCombatCoordinator가 PlayerController를 참조해 기존 기능을 호출한다. 원본 상속이나 전면 수정 없이 새 정책을 추가했다.
2. **이벤트**: `Action<KatanaEvent>`는 발생 사실을 구독자에게 알린다. `RequestNormalAttack()`은 요청이고 `NormalStarted`는 수락 후 알림이다. 요청과 결과를 구분해야 실패한 입력이 애니메이션을 재생하지 않는다.
3. **상속·다형성**: KatanaDamageReceiver는 DamageReceiver를 상속하고 TakeDamage를 override한다. 적은 그대로 IDamageable을 호출하지만 수신자는 먼저 쳐내기를 판정할 수 있다. 실패 때만 base.TakeDamage로 원래 이벤트를 전달한다.
4. **불변 데이터**: KatanaEvent와 KatanaParryResult는 readonly struct와 읽기 전용 프로퍼티로 결과를 전달한다. 구독자가 다른 구독자의 데이터를 바꾸지 않는다.
5. **시간**: Coordinator는 Time.deltaTime을 누적한 게임 시계를 사용한다. Player.IsPaused일 때 누적하지 않는다. timeScale이 0이면 신규 전투 요청도 받지 않는다. 실패 창과 재시도 시간은 별도다.
6. **실행 순서**: Coordinator -50 → Input -40 → 기본 순서의 적 공격. 같은 프레임의 버튼 누름을 적의 Update 타격 전에 반영한다.
7. **Animator와 판정 분리**: ActionProgress로 클립 재생 위치를 맞춘다. 기존 드라이버가 실제 타격 시점을 소유한다. Normal 클립을 쳐내기에 쓰더라도 드라이버의 NormalAttack 상태로 들어가지 않아 피해가 추가되지 않는다.
8. **공유 에셋과 인스턴스**: 카타나 재질은 새 파일이며, 성공 시 검 색은 MaterialPropertyBlock으로 인스턴스에만 적용한다. 원본 공유 재질을 매 프레임 바꾸지 않는다.

핵심 일반 공격 흐름:

```text
좌클릭 → KatanaInputCommandAdapter
→ KatanaCombatCoordinator.RequestNormalAttack()
→ 기존 PlayerController.RequestNormalAttack()
→ AttackStarted → NormalStarted → KatanaWeaponVisual
→ 기존 PlayerTestActionDriver → PlayerAnimationEventRelay
→ NotifyNormalAttackImpact(actionId)
→ IPlayerCombatService.ResolvePlayerAttack(request)
→ 기존 HitConfirmed / Missed / DeathConfirmed
→ 동작 종료 → StrikeEnded → Recovery → DrawnWaiting 또는 납도
```

#### 연결 및 협업 — 팀원 공유용

**게임 입력 담당**

- 사용할 클래스: `BlindBlade.Player.Katana.KatanaCombatCoordinator`.
- `SetMovementInput(Vector2)` / `AddLookInput(Vector2)`는 기존 이동·시점으로 전달한다.
- `RequestNormalAttack()`, `BeginCharge()`, `RequestIaidoAttack()`, `RequestParry()`는 bool 수락 여부를 반환한다. false는 큐에 저장하지 않는다.
- `EndCharge()`는 충전 버튼을 놓았을 때 호출한다.
- `RequestParry()`는 우클릭의 최초 눌림에만 호출한다. 눌린 매 프레임 호출하면 안 된다.
- `SetPaused(bool)`는 기존 플레이어의 상위 일시정지 상태를 함께 전환한다.
- 실제 게임 입력 시스템 연결 시 새 KatanaInputCommandAdapter를 비활성화하고 위 API로 연결한다. 기존 PlayerInputCommandAdapter도 동시에 켜지 않는다.

**적 공격 담당**

- 기존 `IDamageable.TakeDamage(DamageContext)` 호출을 유지한다. 플레이어 루트에는 KatanaDamageReceiver 하나만 연결한다. 다른 IDamageable을 같은 검색 경로에 중복 배치하지 않는다.
- DamageContext: Amount(피해량), Instigator(공격자 GameObject), Point(타격 위치), Direction(공격 방향), PatternId(패턴명).
- 현재 허용 조건은 공격자 루트에서 해당 PatternId가 유일하게 식별되고, 그 패턴이 EnemyMeleeAttack이며 Active 상태이고, 플레이어 전방 각도 안에 있는 경우다. 돌진·투사체·후방은 실패하여 원래 피해로 전달한다.
- 적의 기존 근접 타격은 피해 호출 전에 HashSet으로 동일 수신자의 중복 타격을 제외한다. Coordinator도 한 번 성공하면 창을 즉시 닫는다. PatternId 자체를 공격 1회 ID로 간주하지 않는다.
- `KatanaCombatCoordinator.ParrySucceeded`: 발행자 Coordinator, 구독자는 추후 적 반응/효과 담당. 타입 `Action<KatanaParryResult>`.
- KatanaParryResult.Incoming은 차단한 원래 DamageContext이고 Strike는 성공 순번 1 또는 2다. 실제 타격 수신 중 성공 판정 직후 한 번 발행한다.
- 성공은 들어온 피해 전달을 소비한다. 일반 공격 요청, 반격 피해, 적 공격 취소, 적 경직·넉백은 자동 실행하지 않는다.
- `TryParryIncoming(DamageContext, bool eligible)`는 피해 적용 직전 Receiver가 호출하는 판정 함수다. true면 해당 피해가 차단됨. 임의 성공을 만들기 위한 입력 API가 아니다.

**플레이어 HP / 피격 담당**

- KatanaDamageReceiver에서 상속받은 `DamageReceived: Action<DamageContext>` 또는 Inspector의 `_onDamageReceived`를 연결한다.
- 쳐내기 실패·불가 타격에만 원래 피해가 전달된다. 여기에서 체력·사망을 처리한다. 이 버전은 HP를 중복 구현하지 않았다.

**공격 판정 담당**

- 기존 `IPlayerCombatService.ResolvePlayerAttack(PlayerAttackRequest)` 유지.
- 발도는 `PlayerAttackKind.IaidoFinisher`로 1회 요청하며, 기존 EnemyCombatService가 대상의 남은 HP를 적용해 사망 결과를 반환한다.
- 새 쳐내기 성공 베기는 위 공격 요청을 만들지 않는다.

**애니메이션 / 디버그 담당**

- `EventRaised: Action<KatanaEvent>`의 발행자는 Coordinator, 현재 구독자는 KatanaWeaponVisual과 KatanaDebugOverlay다.
- 데이터는 Stage, Strike, ActionId, WasDrawn, Detail. ActionId는 기존 PlayerController 행동 ID이며 **쳐내기 시도 고유 ID가 아니다**.
- 단계: NormalStarted, StrikeEnded, ParryAttempted/Succeeded/Failed/MotionEnded, DrawnWaiting, SheatheStarted/Ended, ChargeStarted/Ready/Released, DashStarted, SlashStarted, Died, RequestRejected, ChainExpired.
