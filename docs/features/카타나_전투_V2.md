### 카타나 전투 V2

#### 2026-10-11 1인칭 교전 규칙 갱신

- 일반 공격의 최신 규칙은 [1인칭 근접 교전의 1단계](1인칭_근접_교전.md)를 따른다. 발도 1타 → 기존 Normal1의 2타 → 기존 Normal2의 3타와 다음 클릭 1회 예약을 사용하고, 3타 후 회복·납도를 거쳐 다시 발도로 시작한다. 일반 1타는 발도 클립의 삽입 이전 구간만 재생하며 충전 발도·패링 단발 반격은 별도 흐름을 유지한다. 과거 단일 타수·자동 공격 패링 설명은 최신 규칙을 대체하지 않는다.
- 연계가 새로 시작되는 좌클릭은 유효한 감지 적이 화면 중앙 1/3 안, 최대 돌진 거리 이내에 있으면 해당 적에게 돌진 후 1타 `IaidoDoubleSlash` 강공격 베기를 실행한다. 기존 강공격 즉사 판정을 사용하고, 처치가 확정되면 다음 유효 감지 적을 자동으로 선택해 추가 클릭 없이 이어서 돌진한다. 다음 적에는 2타 `Normal1`, 그다음 적에는 3타 `Normal2` 모션을 사용하고, 세 타 뒤에는 1타부터 순환한다. 각 타격 판정은 강공격 즉사다. 다음 대상이 없거나 처치되지 않으면 회복·납도한다. 적이 선택되지 않거나 서비스가 연결되지 않으면 기존 1타 공격으로 진행한다. 구현과 조건은 위 1인칭 근접 교전 명세를 따른다.
- Player 프리팹의 KatanaWeaponVisual에서 2타 AnimationClip·3타 AnimationClip 및 각 적중 진행도를 교체할 수 있다. 공유 Animator Controller 대신 플레이어 전용 런타임 Override를 사용한다. 패링 반격은 원래 Normal2와 별도 진행도를 유지한다. PlayerAttackSlashVfx의 1·2·3타 VFX에는 각각 프리팹 자식 ParticleSystem을 연결하고 해당 자식 Transform을 직접 편집한다. 기본 2·3타 VFX 자식과 슬롯을 Player 프리팹에 저장했다. 세부 연결·검증은 위 교전 명세를 따른다.

- 현재 일반 공격·우클릭 가드·패링·적 칼날 Trigger·EnemySlash·일반 시야 규칙은 [1인칭 근접 교전](1인칭_근접_교전.md)을 따른다. 아래의 이전 판정·자동 패링·검증 기록은 해당 시점의 기록이며 이번 변경의 Play 검증을 의미하지 않는다.

- 기능 설명: 기존 플레이어 이동·충전·공격 판정·Recovery를 유지하면서, 단일 좌클릭 발도 공격과 공격 시작부터 적중 직전까지의 쳐내기, 자동 납도를 별도 버전으로 제공한다.
- 동작 조건 및 처리 흐름: KatanaInputCommandAdapter → KatanaCombatCoordinator → 기존 PlayerController. 표현은 KatanaWeaponVisual → KatanaV2.controller → Sword/Saya 커브. 들어오는 타격은 KatanaDamageReceiver → 쳐내기 또는 기존 DamageReceiver 이벤트로 전달한다.
- 구현 상태: A 자동 구현으로 V2 전투·카타나 리그를 구성했다. 단일 좌클릭 발도와 패링/무패링 판정 흐름은 Stairwell Play Mode에서 런타임으로 확인했다. 물리 마우스 입력과 실제 적의 활성 근접 타격 연동은 미확인이다.

#### 원본 보존

- 기존 Assets/Scripts/Player 코드와 Assets/Animations/PlayerWeapon 에셋을 보존했다. 카타나 전투는 별도 프리뷰 씬 대신 공유 Player 프리팹에서 실행한다.
- 새 씬에서 구 입력/검 표시 컴포넌트는 비활성화하고 구 검 리그도 비활성 상태로 남긴다. 구 에셋이나 클래스는 삭제하지 않는다.
- 새 카타나 리그·Controller·수정할 클립·재질은 새 GUID를 가진 별도 에셋이다. 복제된 스크립트 클래스 중복 선언은 없다.
- 기존 칼날·칼집 메시를 공유하되 메시 내용은 바꾸지 않는다. 새 리그에 코등이·손잡이 장식을 추가하고 새 재질을 사용한다. 손·팔 모델은 추가하지 않았다.
- Dead 클립은 원본을 참조만 한다. Intro·Normal3·Guard 계열은 원본에 남겨 두고 새 Controller 흐름에서 제외한다.
- Normal1·Normal2·IaidoDoubleSlash의 첫 키 연결만 조정했다. 이후 기존 베기 키·커브는 유지한다.
- 문서 목록에는 이 명세 링크만 추가한다. 기존 문서 본문은 덮어쓰지 않는다.

#### 사용 방법

1. 현재 플레이 씬 중 하나를 연다. 카타나 전투 입력과 표현은 공유 Player 프리팹에서 제공한다.
2. 게임 창을 한 번 클릭해 커서를 잠근다. 이 첫 클릭은 공격·쳐내기에 사용하지 않는다.
3. WASD 이동과 마우스 시점은 기존대로 사용한다. 좌클릭에서 유효한 감지 대상이 선택되면 대상까지 돌진한 뒤 `IaidoDoubleSlash` 강공격으로 즉사시킨다. 처치가 확정되면 다음 감지 적을 자동으로 찾아 연속 공격한다. 대상이 없으면 현재 1인칭 근접 교전 명세의 일반 공격·연계를 따른다. 우클릭은 이 V2 규칙에서 전투 동작에 사용하지 않으며 Esc는 커서를 해제한다.
4. 공격 후에는 기존 일반공격 Recovery 0.25초를 적용한다. Recovery와 패링 성공 모션이 끝난 뒤 0.8초가 지나면 자동 납도한다. 동작 중 들어온 추가 좌클릭 입력은 예약하지 않는다.
5. 패링 대상은 기존 판정대로 전방 120도 안에서 공격 활성 상태인 적의 근접 공격이다. 원거리·돌진·후방 공격은 패링되지 않는다. 첫 클릭은 커서 잠금에만 사용되므로 클릭 후 한 번 더 좌클릭해야 공격한다.
6. 피격이 전달되면 HUD의 Incoming damage forwarded와 Console 로그로 확인한다. 이 씬에 플레이어 HP 기능을 추가하지 않았으므로 체력 감소·사망은 별도 수신 시스템이 연결해야 한다.
7. 이번 씬에는 기존 F8 가드 검사 기능을 연결하지 않는다. 실제 적의 공격을 사용한다.

#### 상태 전환과 설계 이유

전투 행동과 검의 물리적 자세를 구분한다. `PlayerController.CurrentState`는 기존 상태이고, `KatanaWeaponState`는 Sheathed / Drawn / Sheathing이다. 쳐내기 시도와 성공 동작은 Coordinator가 별도로 소유한다.

- 좌클릭: 새 공격 연계가 시작될 때 감지 대상을 고를 수 있으면 대상 지정 돌진 후 `IaidoDoubleSlash` 강공격 즉사 판정을 한다. 처치 뒤 다음 유효 대상이 있으면 회복·납도 없이 연속 돌진한다. 대상이 없으면 [1인칭 근접 교전](1인칭_근접_교전.md)의 기존 연계 입력을 따른다.
- 공격 시작부터 적중 직전: Coordinator가 쳐내기 창을 유지한다. 유효한 전방 근접 타격을 받으면 incoming 피해를 소비하고 `PlayerController.CancelNormalAttack(actionId)`로 outgoing 공격을 취소한다. 모션은 같은 발도 클립을 끝까지 재생한다.
- 패링 없음: 발도 클립의 적중 시각에 기존 `NotifyNormalAttackImpact`가 한 번 호출되고, 종료 시점에 기존 NormalAttack Recovery를 적용한다.
- 충전: 납도 대기에서 검과 칼집 전체를 함께 움직인다. 이미 발도된 경우 ChargeFromDrawn의 앞부분에서 먼저 납도한다. 기존 충전 시계는 그대로 진행한다.
- 충전 취소: ChargeRelease로 납도 대기 복귀. 다시 검을 뽑지 않는다.
- 강공격: 기존 대시 → Double Slash → 마지막 베기 판정 1회 → 기존 결과별 Recovery. 베기 종료 후 납도한다.
- 독립 우클릭 패링과 Normal1/Normal2 연계는 사용하지 않는다. 우클릭 입력은 카타나 입력 어댑터에서 소비하지 않는다.
- 좌클릭은 같은 발도 클립을 재생한다. 적의 유효 공격이 발도 적중 시각 전에 도착하면 방어 결과로 처리하고 플레이어 공격만 취소한다. 적 공격이 없으면 기존 일반공격 판정을 실행한다.
- 일시정지는 기존 Controller를 통해 전달하며 카타나의 시계도 멈춘다. 사망 이벤트는 쳐내기와 연계를 취소한다.

선택 이유: 기존 PlayerController가 sealed이며 이동·발소리·맵 연결이 이 타입을 사용한다. 이를 통째로 복제하면 Relay·입력·팀 참조까지 복제가 늘어난다. 따라서 명령 창구를 앞에 추가하는 합성(composition)을 사용했다. Animator가 판정까지 소유하는 방식으로 바꾸면 기존 드라이버와 중복 판정 위험이 있으므로 이번에는 유지했다.

주의: 쳐내기 성공 표현 중 기존 PlayerController 상태는 Free일 수 있다. 신규 게임 입력 시스템은 반드시 Coordinator의 명령과 CanStartAction을 사용해야 한다. 기존 Controller를 직접 호출하면 카타나 명령 제한을 우회한다.

#### Unity / C# 학습 포인트

1. **합성**: KatanaCombatCoordinator가 PlayerController를 참조해 기존 기능을 호출한다. 원본 상속이나 전면 수정 없이 새 정책을 추가했다.
2. **이벤트**: `Action<KatanaEvent>`는 발생 사실을 구독자에게 알린다. `RequestAttack()`은 요청이고 `NormalStarted`는 수락 후 알림이다. 요청과 결과를 구분해 실패한 입력이 애니메이션을 재생하지 않게 한다.
3. **상속·다형성**: KatanaDamageReceiver는 DamageReceiver를 상속하고 TakeDamage를 override한다. 적은 그대로 IDamageable을 호출하지만 수신자는 먼저 쳐내기를 판정할 수 있다. 실패 때만 base.TakeDamage로 원래 이벤트를 전달한다.
4. **불변 데이터**: KatanaEvent와 KatanaParryResult는 readonly struct와 읽기 전용 프로퍼티로 결과를 전달한다. 구독자가 다른 구독자의 데이터를 바꾸지 않는다.
5. **시간**: Coordinator는 Time.deltaTime을 누적한 게임 시계를 사용한다. Player.IsPaused일 때 누적하지 않는다. 쳐내기 창은 `PlayerActionDriver`의 IaidoHitTime에 맞춰 닫히며, 공격 hit 시점 이후에는 열려 있지 않다.
6. **실행 순서**: Coordinator -50 → Input -40 → 기본 순서의 적 공격. 같은 프레임의 버튼 누름을 적의 Update 타격 전에 반영한다.
7. **Animator와 판정 분리**: ActionProgress로 발도 클립 재생 위치를 맞춘다. 기존 드라이버가 실제 타격 시점을 소유하며, 발도 모션 중 쳐내기가 성공하면 같은 모션만 이어지고 피해 callback은 취소된다.
8. **공유 에셋과 인스턴스**: 카타나 재질은 새 파일이며, 성공 시 검 색은 MaterialPropertyBlock으로 인스턴스에만 적용한다. 원본 공유 재질을 매 프레임 바꾸지 않는다.

핵심 일반 공격 흐름:

```text
좌클릭 → KatanaInputCommandAdapter
→ KatanaCombatCoordinator.RequestAttack()
→ 기존 PlayerController.RequestNormalAttack()
→ AttackStarted → NormalStarted → IaidoDoubleSlash 재생 + 패링 창 시작
→ 유효한 적 타격이면 피해 차단 + outgoing 행동 취소 + 같은 모션 지속
→ 적 타격이 없으면 IaidoHitTime에 도달
→ 기존 PlayerActionDriver → PlayerAnimationEventRelay
→ NotifyNormalAttackImpact(actionId)
→ IPlayerCombatService.ResolvePlayerAttack(request)
→ 기존 HitConfirmed / Missed / DeathConfirmed
→ 동작 종료 → StrikeEnded → Recovery → DrawnWaiting 또는 납도
```

#### 연결 및 협업 — 팀원 공유용

**게임 입력 담당**

- 사용할 클래스: `KatanaCombatCoordinator`.
- `SetMovementInput(Vector2)` / `AddLookInput(Vector2)`는 기존 이동·시점으로 전달한다.
- `RequestAttack()`은 단일 발도 공격 요청이며 bool 수락 여부를 반환한다. 기존 호출 호환을 위해 `RequestNormalAttack()`과 `RequestNormalAttackWithParry()`도 같은 흐름을 부른다. 입력은 자동 큐에 저장하지 않는다.
- `BeginCharge()`, `RequestIaidoAttack()`은 이전 충전 시스템 호환용으로 남아 있으며, 좌클릭의 단일 공격 경로는 이를 사용하지 않는다.
- `EndCharge()`는 충전 버튼을 놓았을 때 호출한다.
- 공격 모션은 `IaidoDoubleSlash`지만, 공격 판정은 기존 `PlayerController.RequestNormalAttack()` 경로를 사용해 `PlayerAttackKind.Normal`로 적 시스템에 전달한다.
- 패링 창은 발도 프로필의 적중 시간까지 열린다. 성공하면 `PlayerController.CancelNormalAttack(int)`가 ActionId를 검증하고 outgoing 판정을 취소한다. 패링 성공 모션은 동일한 클립의 끝까지 계속된다.
- `SetPaused(bool)`는 기존 플레이어의 상위 일시정지 상태를 함께 전환한다.
- 실제 게임 입력 시스템 연결 시 새 KatanaInputCommandAdapter를 비활성화하고 위 API로 연결한다. 기존 PlayerInputCommandAdapter도 동시에 켜지 않는다.

**적 공격 담당**

- 기존 `IDamageable.TakeDamage(DamageContext)` 호출을 유지한다. 플레이어 루트에는 KatanaDamageReceiver 하나만 연결한다. 다른 IDamageable을 같은 검색 경로에 중복 배치하지 않는다.
- DamageContext: Amount(피해량), Instigator(공격자 GameObject), Point(타격 위치), Direction(공격 방향), PatternId(패턴명).
- 현재 허용 조건은 공격자 루트에서 해당 PatternId가 유일하게 식별되고, 그 패턴이 EnemyMeleeAttack이며 Active 상태이고, 플레이어 전방 각도 안에 있는 경우다. 돌진·투사체·후방은 실패하여 원래 피해로 전달한다.
- 적의 기존 근접 타격은 피해 호출 전에 HashSet으로 동일 수신자의 중복 타격을 제외한다. Coordinator도 한 번 성공하면 창을 즉시 닫는다. PatternId 자체를 공격 1회 ID로 간주하지 않는다.
- `KatanaCombatCoordinator.ParrySucceeded`: 발행자 Coordinator, 구독자는 추후 적 반응/효과 담당. 타입 `Action<KatanaParryResult>`.
- KatanaParryResult.Incoming은 차단한 원래 DamageContext이고 Strike는 단일 행동 호환 필드로 항상 1이다. 실제 타격 수신 중 성공 판정 직후 한 번 발행한다.
- 성공은 들어온 피해 전달을 소비한다. 일반 공격 요청, 반격 피해, 적 공격 취소, 적 경직·넉백은 자동 실행하지 않는다.
- `TryParryIncoming(DamageContext, bool eligible)`는 피해 적용 직전 Receiver가 호출하는 판정 함수다. true면 해당 피해가 차단됨. 임의 성공을 만들기 위한 입력 API가 아니다.

**플레이어 HP / 피격 담당**

- KatanaDamageReceiver에서 상속받은 `DamageReceived: Action<DamageContext>` 또는 Inspector의 `_onDamageReceived`를 연결한다.
- 쳐내기 실패·불가 타격에만 원래 피해가 전달된다. 여기에서 체력·사망을 처리한다. 이 버전은 HP를 중복 구현하지 않았다.

**공격 판정 담당**

- 기존 `IPlayerCombatService.ResolvePlayerAttack(PlayerAttackRequest)` 유지.
- 좌클릭 발도 모션은 `PlayerAttackKind.Normal`로 1회 요청한다. 충전·대시·IaidoFinisher 즉사 계약을 사용하지 않는다.
- 쳐내기 성공 시 기존 일반공격 ActionId를 취소해 공격 요청을 만들지 않는다.

**애니메이션 / 디버그 담당**

- `EventRaised: Action<KatanaEvent>`의 발행자는 Coordinator, 현재 구독자는 KatanaWeaponVisual과 KatanaDebugOverlay다.
- 데이터는 Stage, Strike, ActionId, WasDrawn, Detail. ActionId는 기존 PlayerController 행동 ID이며 **쳐내기 시도 고유 ID가 아니다**.
- 단계: NormalStarted, StrikeEnded, ParryAttempted/WindowClosed/Succeeded/Failed/MotionEnded, DrawnWaiting, SheatheStarted/Ended, ChargeStarted/Ready/Released, DashStarted, SlashStarted, Died, RequestRejected. `NormalStarted`는 단일 Iaido 모션 시작이며 Strike 값은 1이다.
- 실제 피해 및 행동 종료는 기존 드라이버·Relay가 소유한다. 클립에 피해 Animation Event를 별도로 추가하지 않는다.

**발소리 / 맵 담당**

- 기존 PlayerController의 FootstepEmitted와 PlayerFootstepEvent를 GameSceneInitializer가 구독한다. 카타나 때문에 발소리 생산자를 추가하지 않았다.
- `_perceptionProviderSource`가 연결되지 않은 씬에서는 `EnemyCombatService`가 같은 씬의 활성 생존 적을 후보로 공급하며 화면 중앙·최대 거리 조건을 적용한다. 전투 서비스까지 연결되지 않은 경우에는 대상 지정 돌진 대신 기존 일반 공격으로 진행한다. 파괴 가능한 벽 계약은 별도 맵 서비스 연결이 필요하며, 돌진 중 비파괴 벽은 기존처럼 공격을 막는다.
- 쳐내기 성공 뒤 기존 Controller는 일반공격 Recovery를 거친다. 같은 Iaido 클립이 끝날 때까지 Coordinator가 신규 행동을 제한한다.
