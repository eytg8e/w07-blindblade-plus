### 스테이지 이동과 T자 복도

- 2026-10-10 검 소음 초기화 통합: TCorridor의 독립 StageSwordNoise 오브젝트를 제거했다. GameSceneInitializer의 Use Sword Noise가 켜져 있으면 같은 오브젝트에 컴포넌트를 생성하고 현재 씬의 EnemyController를 한 번 수집해 Initialize(player, enemies, hearingDistance, alertDuration)로 연결한다. 기본 청각 거리 40m·수색 시간 15초와 기존 검 행동·NavMesh 거리 판정을 유지한다. Initializer 종료 시 Shutdown으로 구독을 해제하고 컴포넌트를 제거한다.
- 해당 설정은 TCorridor의 GameSceneInitializer에서 조절하며 별도 적 목록 연결은 필요 없다. Unity 컴파일 오류·경고 0개, Play에서 컴포넌트 1개·현재 씬 적 2개 연결, AlertEnemies 후 양쪽 Searching, RequestNormalAttack 후 행동 ID 수신 및 Shutdown 참조 해제를 확인했다. 물리 키 입력은 재검증하지 않았다.

- 2026-10-10 BGM 연결: 사용자가 만든 event:/StairWell을 BGM Bank에 배정하고 Desktop BGM 및 Master Bank를 빌드했다. StairwellBGM의 StairwellMusic._fmodEvent에 GUID 4a5831ba-d0f3-4813-86bd-72c93d8850cb를 연결했다. 실제 Stairwell Play에서 PLAYING, FMOD RESULT.OK, Volume=0.7, is3D=false를 확인했다. 아래 이벤트 미지정 설명은 최초 구현 당시 상태이다.

- 2026-10-10 동선 수정: T자 교차점 정면의 빈 공간을 CrossbarNorthCenter 벽으로 막아 좌우 복도로 이동하도록 했다. 사용자 작업에서 삭제된 중앙 문은 복구하지 않았다. 양끝 적 배치와 소리 반응은 유지하며 NavMesh를 다시 베이크했다. 중앙 정면 Collider.Raycast 차단과 양쪽 NavMesh PathComplete를 확인했다. 아래 마지막 문 관련 기록은 최초 구현 검증 이력이다.

- 기능 설명: 발전 기획의 스테이지 이동 시스템 2·3번을 구현한다. 첫 복도 끝 문 → 적 없는 계단 → 두 적이 있는 T자 복도로 이동한다.
- 동작 조건 및 처리 흐름: StraightCorridor에서 적을 처치하고 문 근처에서 F를 누른 뒤 통과한다. Stairwell에서 실제 계단으로 3m 올라가 위층 문을 열고 통과하면 TCorridor가 로드된다. E는 기존 검 차징 입력이므로 문에는 F를 사용한다.
- 구현 상태: 세 씬과 Build Settings 연결, 문 개방, 계단, FMOD BGM 슬롯, 두 적 순찰 및 검 소리 반응 완료. 계단 BGM 이벤트는 사용자가 선택할 수 있도록 비워 두었다. T자 복도 이후의 3스테이지는 이번 범위에 포함하지 않아 마지막 문의 Next Scene은 비어 있다.

#### 연결 및 협업

- 연결된 기능: 기존 PlayerController.ActionEvent, EnemyHealth.IsAlive, NavMeshAgent, Managers.Scene.LoadSceneAsync, CorridorRoundController의 GameOver·재시작을 사용한다. 검 소리는 FMOD 오디오 분석 대신 실제 검 휘두르기 시작 이벤트를 기준으로 처리한다.
- 공유하는 코드 및 상태: StageSwordNoise는 같은 씬의 살아 있는 적에 대해서만 완전한 NavMesh 경로 길이를 계산한다. 40m 이내이면 HearNoise(position, 15초)를 전달한다. 적은 마지막 소리 위치로 이동하다 감지 반경 6m에서 플레이어를 발견하면 기존 돌진·근접 공격을 사용한다.
- 중복 또는 충돌 사항: 적은 기존 복도 적과 같은 설정이며 순찰 속도 1.5m/s, 순찰 거리 3m, 돌진 속도 12m/s를 유지한다. 양끝 시작 위치는 (-11, 0, 10), (11, 0, 10), 플레이어는 (0, 0.1, -10)이다. 다른 층의 적은 소리를 듣지 않는다. 계단 BGM은 이동 중 효과음 제한과 별도로 재생한다.
- 승인 필요 사항 및 결과: 사용자 A 자동 구현 및 기능 자동 커밋 지시에 따라 진행했다. 기존 FMOD 프로젝트의 사용자 작업은 수정하지 않는다.

#### Inspector 설정

- 문: StageDoor의 Required Enemies, Next Scene, Interaction Distance(2.5m), Opening Duration(0.6초), Open Angle(-100도)을 조절한다. 첫 문은 적 한 명, 마지막 문은 적 두 명을 모두 처치해야 열린다.
- 적 소리 반응: TCorridor의 GameSceneInitializer에서 Use Sword Noise, Sword Hearing Distance(경로 길이 40m), Sword Alert Duration(15초)을 조절한다.
- 계단 BGM: 음원 파일을 FMOD Studio 프로젝트에 가져와 2D 루프 이벤트를 만든다. BGM_Bus에 라우팅하고 Bank에 넣어 Build한다. Unity에서 Stairwell 씬의 StairwellBGM → StairwellMusic → Fmod Event에 해당 이벤트를 선택한다. Volume 기본값은 0.7이다. Unity AudioSource는 사용하지 않는다.

#### 검증

- Unity 컴파일 완료, errors=[]를 확인했다. 문 앞 안내 문구를 Game View 캡처에서 확인했다.
- 첫 적 생존 시 문 개방 실패, 처치 후 개방·통과에 따른 Stairwell 로드를 확인했다.
- 계단에 적이 없고 CharacterController가 12단 계단을 실제로 올라 3m 높이에 도달하는 것을 확인했다. 위층 문 통과 후 TCorridor 전환도 확인했다.
- 임시 기존 2D 루프 FMOD 이벤트로 PLAYING 상태를 확인했고, 계단 이탈 후 인스턴스 수가 0으로 돌아왔다. 최종 씬에는 임시 이벤트를 저장하지 않았다. 사용자가 선택할 긴장 BGM의 실제 청감은 미확인이다.
- T자 복도 적 두 명의 초기 Patrolling, 양쪽 PathComplete, 실제 검 공격 시작 후 양쪽 Searching 및 소리 위치 목적지를 확인했다. 이후 접근·공격과 기존 GameOver까지 확인했다.
- 한 적만 처치했을 때 마지막 문은 잠겨 있고, 둘 다 처치하면 열린다. T자 복도 GameOver 후 Restart가 TCorridor를 유지하며 적 두 명과 GameOver=false를 복구하는 것을 확인했다.
- 검증은 일시적인 Editor 실행으로 수행했으며 테스트 코드를 저장하지 않았다.

#### 복도 적을 현재 프리팹 기반으로 통일 (2026-10-10)

- 사용자 A 자동 구현 승인으로 TCorridor의 Enemy_LeftEnd 원본 GUID를 현재 Enemy_SingleMelee.prefab으로 복구하고, 프리팹에서 분리되어 있던 Enemy_RightEnd를 같은 프리팹의 연결된 인스턴스로 전환했다. 런타임 적 생성기는 추가하지 않는다.
- 원본 프리팹의 외형·체력·발자국·순찰·근접 공격을 상속하며 원본을 수정하지 않는다. 양쪽 배치 위치 (-11, 0, 10), (11, 0, 10), 중앙을 바라보는 회전, 플레이어 Target, 감지 반경 6m, 이동 속도 1.5m/s를 유지한다. 씬 전용 CorridorCharge(속도 12m/s)와 돌진→근접 Patterns는 프리팹 인스턴스의 추가 컴포넌트 및 오버라이드로 유지한다.
- 실제 인터페이스: StageSwordNoise._enemies의 EnemyController 참조와 StageDoor._requiredEnemies의 EnemyHealth 참조가 사용하는 씬 ID를 보존했다. 검 행동 이벤트 시 AlertEnemies→HearNoise, 문 잠금 검사 시 EnemyHealth.IsAlive 호출 흐름은 변경하지 않았다. 팀원은 공통 외형·체력을 Enemy_SingleMelee 프리팹에서 수정하고 복도별 위치·감지·속도는 씬 인스턴스에서 조절한다.
- 선택 이유: 씬의 독립 복제본 대신 Unity PrefabInstance와 인스턴스 오버라이드를 사용해 공통 프리팹 변경을 상속하면서 기존 복도 전투를 유지한다. 별도 런타임 생성기나 새 공통 프리팹은 필요하지 않아 추가하지 않았다.
- 정적 검증: T자 복도 적 인스턴스 2개 및 직선 복도 1개가 현재 프리팹 GUID를 참조한다. 원본 컴포넌트 ID 일치, 씬 내부 참조 누락 및 중복 ID 없음. Unity Pipeline이 응답하지 않고 배치 실행은 프로젝트 사용 중 오류로 종료되어 실제 씬 로드·컴파일·Play 검증은 미확인이다. 테스트 코드는 작성하지 않았다.
- 남은 확인: Unity에서 프리팹 연결, 연기 외형 표시, 양쪽 순찰·검 소리 반응·처치 후 문 조건을 Play로 확인한다. 현재 dev 브랜치에서는 저장소 지침에 따라 Git CLI와 커밋을 수행하지 않았다.
