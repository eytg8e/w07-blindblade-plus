# BlindBlade 플레이어 시스템 인수인계

## 프로젝트와 테스트 위치

실제 개발 대상은 `week06-blindblade`야. `W06-POC_HS/WhistlePOC`는 시각·게임플레이 참고 자료고, 새 프로젝트의 코드를 이어 붙이는 대상은 아니야.

실제 플레이 경로에서 사용하는 플레이어는 공유 [Player.prefab](C:/Users/JUNGLE/Documents/GitHub/week06-blindblade/Assets/Resources/Prefabs/Player.prefab)이야. `Stairwell`, `TCorridor`, `StraightCorridor`, `MainMap` 씬이 이 프리팹을 사용해.

## 현재 조작과 전투 흐름

- WASD: 이동
- 마우스: 시점 회전
- 좌클릭: 단일 발도 모션으로 공격 및 공격 직전 패링 시도
- Ctrl 홀드: 웅크리기
- C: 웅크리기 토글
- Esc: 커서 잠금 해제

게임 창에서 커서가 풀린 상태의 첫 클릭은 커서 잠금에 사용돼. 잠긴 뒤 좌클릭해야 공격이 나가. 현재 입력 어댑터에는 우클릭 가드 입력이 없어. `PlayerController`의 기존 가드 API는 남아 있지만 새 입력 흐름에서는 사용하지 않아.

좌클릭 흐름은 다음과 같아.

1. `KatanaInputCommandAdapter`가 `KatanaCombatCoordinator.RequestAttack()`을 호출한다.
2. 코디네이터가 기존 `PlayerController.RequestNormalAttack()`을 시작한다.
3. `KatanaWeaponVisual`은 공격 애니메이션으로 `IaidoDoubleSlash`를 재생한다.
4. 공격 시작부터 적중 시점 전까지 패링 창을 연다.
5. 적중할 공격이 없으면 기존 일반 공격 판정을 한 번 실행한다.
6. 행동 종료 후 일반 공격 Recovery를 적용하고, 회복 뒤 자동 납도한다.

**중요:** 화면에 재생되는 클립 이름은 `IaidoDoubleSlash`지만, 현재 좌클릭의 게임 판정 종류는 `PlayerAttackKind.Normal`이야. 따라서 충전 발도 강공격의 대시·즉사 판정과는 별개야. 실제 적중 판정도 공격 1회야.

현재 주요 초기값은 다음과 같아.

- 일반 공격 적중 시점: 0.42초
- 공격 동작 종료: 0.72초
- 일반 공격 Recovery: 0.25초
- Recovery 종료 후 자동 납도 대기: 0.8초
- 납도 동작 시간: 0.3초

Recovery 중 입력은 큐에 저장하지 않아. 다만 이동 입력은 최근 요청값을 보관했다가 Recovery가 끝나면 복원하므로, 공격 중에도 W를 누르고 있었다면 회복 종료 후 이동을 다시 시작해.

## 애니메이션 연결

공유 Player 프리팹은 `KatanaV2_Responsive.controller`를 사용해. 활성 클립은 `Assets/Animations/KatanaV2/PoseAligned/Clips/` 아래의 에셋들이야.

- `Rest`: 시작 자세와 납도 후 대기
- `IaidoDoubleSlash`: 좌클릭 공격 및 패링 성공 때 유지되는 공통 모션
- `SheatheIaido`: 공격 뒤 납도
- `Dead`: 사망 이벤트가 전달될 때

`Normal1`, `Normal2`, 충전·대시 관련 클립은 컨트롤러에 남아 있지만 현재 기본 입력 흐름에서는 호출되지 않아. 이름이 같은 발도 클립이 다른 폴더에도 있으니, 현재 수정 대상은 `PoseAligned/Clips/IaidoDoubleSlash.anim`인지 확인해야 해.

클립은 `ActionProgress`로 재생돼. 실제 판정은 0.42초, 종료는 0.72초고, 프리팹의 `_iaidoImpactProgress`는 0.884615야. 베기 타이밍 키를 이동했다면 타격 시각과 화면 모션이 맞는지 다시 확인해야 해.

## 다른 시스템과 연결되는 계약

| 연결 | 실제 계약과 호출 시점 | 담당 및 주의점 |
|---|---|---|
| 플레이어 공격 → 적 전투 | `PlayerController`가 적중 시 `IPlayerCombatService.ResolvePlayerAttack(PlayerAttackRequest)`를 호출. 요청에는 `ActionId`, `Kind`, `PreferredTargetId`, `Origin`, `Direction`, `Range`, `IssuedAt`이 들어가고, 응답은 `HitConfirmed`, `HitTargetId`, `DeathConfirmed`를 반환해. | 적 담당이 판정·피해·사망 확정을 소유해. 현재 `EnemyCombatService`가 구현체야. `ActionId` 기준 중복 판정 방지와 벽 뒤 적 차단이 들어 있어. |
| 적 공격 → 플레이어 | 적이 `IDamageable.TakeDamage(DamageContext)`를 호출해. 문맥은 피해량, 공격자 `Instigator`, 접촉점, 방향, `PatternId`를 포함해. | `KatanaDamageReceiver`가 먼저 패링을 확인하고, 패링되지 않은 피해는 기본 `DamageReceiver` 이벤트로 전달해. 별도 중복 호출은 하지 않아. |
| 패링 가능 조건 | 패링 창 안에서 플레이어의 `NormalAttack`이 진행 중이어야 해. `PatternId`가 적의 단일 공격 컴포넌트와 일치하고, 공격이 활성 상태인 `EnemyMeleeAttack`이며, 플레이어 정면 120도 범위여야 해. | 성공하면 플레이어 피해를 소비하고 진행 중인 공격 판정을 취소해. 별도의 적 경직·밀쳐내기·반격 피해는 현재 없어. 돌진·원거리·후방 공격은 패링 대상이 아니야. |
| 발걸음 → 사운드 | `PlayerMotor.FootstepEmitted`를 `PlayerController.FootstepEmitted`가 전달해. `PlayerFootstepEvent`에는 위치, 시각, Normal/Quiet 유형, 속도, 소음 강도가 있어. | `GameSceneInitializer`가 이를 받아 `SoundId.Footstep` 사운드를 재생해. 이 경로만으로 적 AI가 발소리를 감지하지는 않아. 적의 청각 감지와는 별도 연결이 필요해. |
| 플레이어 상황 → 인지 시스템 | `PlayerController.SenseContextChanged` 및 `IPlayerPerceptionProvider.SetPlayerSenseContext(PlayerSenseContext)`로 이동·집중·충전·이동 모드를 전달해. | 실제 게임용 `IPlayerPerceptionProvider` 구현은 현재 확인되지 않았고 테스트 어댑터만 있어. 적이 들은 대상을 플레이어에게 돌려주려면 구현과 연결이 필요해. |
| 적 인지 대상 → 플레이어 공격 | `IPlayerPerceptionProvider.GetCurrentTargets()`가 `PlayerPerceivedTarget` 목록을 제공해. | 충전 발도 타겟 선정에서 사용해. 현재 충전 입력은 비활성 상태라 기본 좌클릭 공격은 이 대상을 사용하지 않아. |
| 맵 벽 → 플레이어 대시 | `IPlayerMapService.ResolveDashWallContact(...)`가 벽 파괴·통과 가능 여부를 반환해. | 현재 테스트 어댑터 외의 게임용 구현은 확인되지 않았어. 충전 발도 대시를 다시 켤 때 맵 담당과 연결해야 해. |
| 전투·연출 이벤트 | `PlayerController.ActionEvent`는 상태·행동 ID·결과·대상 ID·위치를 전달해. `KatanaCombatCoordinator.EventRaised`는 무기 표현용 단계 이벤트야. | 실제 적중·미스·사망 판정 구독에는 `ActionEvent`를 사용해. `KatanaEvent`는 검 애니메이션과 디버그 표현용이야. |

적의 근접 공격 코드는 활성 판정에서 `DamageContext`를 전달하도록 되어 있어. 현재 패링 확인의 핵심은 **실제 적의 공격이 활성 프레임에 올바른 `PatternId`와 공격자 루트로 플레이어 수신기에 도달하는지**야.

## 피해·체력 연결 상태

`PlayerHealth.cs` 파일은 있지만 공유 `Player.prefab`과 현재 주요 플레이 씬에 붙어 있지 않아. 그래서 현재 플레이어 피격은 `KatanaDamageReceiver`의 이벤트까지 전달될 수 있어도 체력 감소와 사망 처리는 연결되지 않은 상태야.

`PlayerHealth`와 `KatanaDamageReceiver`는 둘 다 `DamageReceiver`/`IDamageable` 계열이므로 같은 플레이어에 무작정 함께 붙이면 적 쪽 `GetComponentInParent<IDamageable>()`가 어느 수신기를 찾는지 모호해질 수 있어. 체력을 붙일 때는 단일 피해 수신 경로로 통합해야 해.

## 프리팹·씬·효과음

- Player 프리팹에는 V2 입력, 코디네이터, 시각화, 피해 수신기, 테스트 액션 드라이버, 디버그 오버레이가 연결돼 있어.
- 각 플레이 씬의 `GameSceneInitializer`는 초기화 시 Player.prefab의 `EnemyCombatService`를 찾아 플레이어 전투 서비스로 연결해.
- `Stairwell`과 `StraightCorridor`에는 `PlayerCombatAudio`가 씬 오버라이드로 추가돼 있어. `Player.prefab` 자체나 `TCorridor`에는 이 컴포넌트가 없어. 효과음 동작이 씬마다 다를 수 있어.
- 같은 씬의 적 피해음은 `EnemyDamageAudio`가 담당해.
- `docs/features/카타나_전투_V2.md`에는 이전 Preview 씬과 컨트롤러 경로가 적혀 있어. 현재 실제 연결은 Player 프리팹과 `PoseAligned/KatanaV2_Responsive.controller`를 기준으로 확인해.

## 검증한 항목과 미확인 항목

- Unity 스크립트 컴파일은 확인했어.
- Stairwell Play Mode에서 공격 요청, 발도 모션, 미스, Recovery, 자동 납도 흐름을 확인했어.
- 패링 성공 흐름은 합성 `DamageContext`를 직접 전달해 확인했어.
- 실제 키보드·마우스 입력과 실제 적의 활성 근접 공격이 연결된 패링은 아직 검증되지 않았어.
- 자동화 테스트 스위트는 추가하거나 실행하지 않았어.

## 다음 팀 작업 제안

1. 실제 적 근접 공격을 앞에서 받는 패링 테스트와 창 밖·후방·돌진 공격 피격 테스트.
2. 플레이어 발걸음 이벤트를 적 청각 감지로 연결하고, 감지 결과를 `IPlayerPerceptionProvider`로 반환.
3. 플레이어 체력·사망을 단일 `IDamageable` 경로에 연결.
4. 패링 성공 때 적을 경직·밀쳐낼지, 현재처럼 피해 차단만 할지 결정.
5. `PlayerCombatAudio`가 필요한 테스트 씬에 공통 적용할지 결정.
6. 애니메이션 이벤트를 도입할지 결정하고, 도입 전까지는 타격 키·`_iaidoImpactProgress`·0.42/0.72초 타이밍을 함께 조정.

팀원이 같은 결과를 보려면 Player 프리팹, 관련 스크립트, Animator Controller, 수정한 Animation Clip과 각각의 `.meta`, 씬 변경분을 함께 동기화해야 해.
