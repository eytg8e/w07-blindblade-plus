#### 기존 게임 씬 적용 기록 (절차적 검기 제거 전)

아래의 절차적 검기 및 Use Outline Vfx 설명은 과거 적용 기록이다. 현재 연결·재생 규칙은 위의 절차적 검기 제거 절을 따른다.

`Stairwell`, `StraightCorridor`, `TCorridor`의 플레이어에는 `PlayerCombatEffects`가 연결되어 있다. 기존 행동 이벤트와 `PlayerActionDriver`의 표현 타이밍을 사용하므로 이 씬에 SwordEffectEmitter·별도 Animation Event를 중복 연결하지 않는다.

| 상황 | 사용하는 프리팹 / 연결 |
| --- | --- |
| 플레이어 일반·발도 베기 | ProceduralSwordSlashVFX. 실제 칼날의 Effect Blade Base·Tip 위치로 재생 |
| 검 접촉 / 쳐내기 성공 | Impact. 기존 접촉 판정 또는 쳐내기 이벤트의 위치로 재생 |
| 검이 적 Collider에 접촉 | Impact와 BloodExplosionSpikyAnimated를 함께 재생 |
| 적 공격 실행 | EnemySlash. EnemyCombatEffects가 AttackCommitted를 구독 |

StraightCorridor의 적 1명, TCorridor의 적 2명에 적 공격 효과를 연결했다. Stairwell에는 실제 적 공격 대상이 없어 해당 연결을 추가하지 않았다. 혈흔은 BloodHit=1, 공용 타격은 SwordClash=2, 플레이어 검기는 SwordSlashTrail=3, 적 검기는 EnemySlash=4를 사용한다.

이 세 씬은 발자국 전용 인지 규칙을 유지한다. PlayerCombatEffects의 Use Outline Vfx는 on이며 플레이어 검기만 OutlineVFX로 표시한다. 검기는 인지 영역 밖에서도 윤곽선이 보이고, 적 공격·Impact·혈흔은 원래 URP 표현을 유지한다. 표시 설정은 재생 인스턴스에만 적용하며 원본 이펙트 프리팹은 변경하지 않는다.

현재 PlayerCombatEffects는 각 씬의 Player 인스턴스에 추가되어 있다. 공용 Player 프리팹만 수정해도 기존 세 씬에 반영된다고 가정하지 않는다. 같은 연결을 새 씬에 구성할 때 Use Outline Vfx를 켜면 검기와 다른 효과의 표시 방식을 분리해 적용한다.

TCorridor의 기존 플레이어 전투 서비스 참조는 미연결 상태로 보존했다. 이 씬은 검의 SwordEffectEmitter로 시각적 접촉·혈흔을 생성하며 피해 판정을 추가하지 않는다. 실제 적중 판정 연결은 플레이어·적 담당자가 별도로 완료해야 한다. 이후 전투 서비스로 통합할 때 Physical Contacts를 해제하고 Contacts를 지정해 중복 재생을 방지한다.

PlayerCombatEffects의 Normal / Iaido Windup Fraction과 Follow Through Fraction은 기존 공격 시간 안에서 검기를 표시할 구간만 조절한다. 실제 공격·피해·사운드 타이밍은 변경하지 않는다.

세 씬 포함 Windows 빌드는 오류 0건·경고 14건으로 통과했다. StraightCorridor의 실제 일반 공격에서 서비스 준비와 게임 카메라의 검기 표시를 확인했다. 전체 전투 흐름의 추가 검증은 사용자 요청으로 중단했다. 즉사로 비활성화된 적에도 혈흔이 생성되도록 마지막 접촉 조건을 보완했으며 이 마지막 조건 변경 뒤에는 재검증하지 않았다.

#### 새 씬에서 준비하기

1. 카메라의 시야와 Culling Mask에 검·접촉 지점이 포함되도록 배치한다. 기존 프로젝트 렌더링 설정을 사용한다.
2. 매니저를 씬마다 복제하지 않는다. 호출자의 Start에서 `Game.Instance`에 접근하면 Game이 EffectManager를 생성·초기화한다. 다른 객체의 Awake에서 이미 준비됐다고 가정하지 않는다.
3. 윤곽선 효과를 사용할 때는 씬 초기화 담당자가 실제 플레이어를 감각 관측자로 연결한다. 기존 연결 코드가 있으면 재사용하고, 적이나 개별 검이 관측자를 덮어쓰지 않는다.

```csharp
// 씬 초기화를 담당하는 MonoBehaviour의 클래스 내부 예시이다.
[SerializeField] private Transform _player;

void Start()
{
    Game.Instance.SensoryManager.SetObserver(_player);
}
```

`OutlineVFX`가 붙은 효과는 인지 영역 안에서만 표시된다. 관측자 미연결 상태에서는 재생에 성공해도 Play 화면에서 보이지 않을 수 있다. 일반 URP 표현은 해당 컴포넌트를 끄거나 제거하면 된다. 자세한 설정은 [화면 공간 윤곽선](화면_공간_윤곽선.md)을 참고한다.

#### 검·공격·애니메이션 연결하기

1. 실제 검에 `SwordEffectEmitter`를 붙인다.
2. Inspector에서 아래 참조를 연결한다.

| 필드 | 연결할 대상 |
| --- | --- |
| Blade Base / Blade Tip | 실제 칼날의 밑점 / 끝점 Transform |
| Owner Root | 검을 소유한 캐릭터의 루트. 이 계층의 Collider는 접촉 대상에서 제외됨 |
| Contact Layers | 타격을 표시할 대상의 Collider 레이어. 감각·상호작용 센서는 제외 |
| Contact Radius | 시각적 접촉 여유 거리. 너무 크면 칼이 닿기 전에 효과가 발생함 |

3. 모든 Start 초기화가 끝난 뒤, 실제 베기 구간에 다음 호출을 연결한다.

| 호출 | 호출 시점 | 결과 |
| --- | --- | --- |
| `BeginSwing()` | 준비 동작 이후 실제 베기 시작 | 접촉 감지 시작. 성공 true, 실패 false |
| `EndSwing()` | 정상적인 베기 종료 | 마지막 접촉 확인 후 감지 종료. Impact는 자연 종료 |
| `CancelSwing()` | 공격 취소·무기 교체·강제 중단 | 해당 검의 접촉 감지 즉시 중단 |

```csharp
// 공격 담당 MonoBehaviour의 클래스 내부 예시이다.
[SerializeField] private SwordEffectEmitter _swordEffects;

/// <summary>
/// 입력 없이 베기 표현을 시작하고 실패하면 안내 메시지를 출력한다.
/// </summary>
public void BeginAttackEffects()
{
    if (!_swordEffects.BeginSwing())
        Debug.LogWarning("[AttackEffects] Unable to start sword effects.", this);
}

/// <summary>
/// 입력 없이 베기 표현을 정상 종료하고 잔상은 자연 종료하도록 유지한다.
/// </summary>
public void EndAttackEffects()
{
    _swordEffects.EndSwing();
}

/// <summary>
/// 입력 없이 취소된 공격의 검기와 접촉 감지를 즉시 정리한다.
/// </summary>
public void CancelAttackEffects()
{
    _swordEffects.CancelSwing();
}
```

세 메서드를 한꺼번에 호출하지 않는다. Animation Event는 위 예시처럼 void 수신 메서드에 연결하고, 내부에서 `BeginSwing()`의 실패 여부를 확인한다. 검 컴포넌트 비활성화 시에는 자동으로 취소되며, 다시 활성화한 뒤에는 새 `BeginSwing()`이 필요하다.

#### 적·맵 담당자가 연결할 내용

- 접촉을 표시할 표면 또는 피격 영역에 Collider를 제공하고, 해당 레이어를 검의 Contact Layers에 포함한다. Trigger도 감지 대상이 될 수 있다. 검의 Rigidbody나 대상의 OnCollisionEnter는 필수가 아니다.
- 검이 접촉 지점을 감지해 공용 타격 효과를 자동 요청한다. 적·벽·바닥에서 같은 접촉의 `PlayHit()`를 다시 호출하지 않는다. EffectId와 접촉 위치를 대상 측에서 전달할 필요가 없다.
- 같은 Collider에는 베기당 한 번 재생한다. 한 대상에 여러 Collider가 있으면 효과가 여러 번 발생할 수 있으므로 실제 배치에서 확인한다.
- 이 감지는 시각 표현용이다. 피해·가드·사망·소리 판정은 기존 전투 코드가 담당하며, 재생 성공을 피해 확정으로 사용하지 않는다. 극단적인 저프레임·빠른 회전의 모든 접촉을 보장하지 않는다.

#### 새 스크립트에서 단발 효과 재생하기

검 접촉 외의 별도 연출이 필요한 경우에만 `Game.Instance.EffectManager`를 사용한다. 예를 들어 혈흔은 자동 검 타격과 별도로 선택해 요청할 수 있다.

```csharp
// MonoBehaviour의 클래스 내부 예시이다. Start 이후에 호출한다.
private EffectManager _effects;

void Start()
{
    _effects = Game.Instance.EffectManager;
}

/// <summary>
/// 월드 hitPosition에 혈흔을 요청하고 재생 요청의 성공 여부를 반환한다.
/// </summary>
public bool ShowBlood(Vector3 hitPosition)
{
    return _effects.Play(EffectId.BloodHit, hitPosition);
}
```

`Play(id, position)`은 월드 위치와 기본 회전, `Play(id, position, rotation)`은 월드 위치와 지정 회전을 사용한다. 반환값은 요청 성공 여부이며, 효과가 끝났다는 뜻은 아니다. 단발은 생성 위치에 남아 자연 종료한다. 호출자가 Instantiate·Destroy·풀 반환을 직접 수행하지 않는다.

| 요청 | 현재 사용 목적 |
| --- | --- |
| `Play(EffectId.BloodHit, position)` | 선택적인 혈흔 연출 |
| `PlayHit(position)` | 공용 Impact. 검 접촉에서는 SwordEffectEmitter가 호출 |
| `EffectId.SwordSlashTrail` | 이전 절차적 검기 ID. 현재 Library 등록 및 자동 호출 제거 |

현재 타격 ID는 `EffectId.SwordHit`이며 연결된 타격 프리팹은 Impact이다. 검기는 `PlayerAttackSlashVfx`로 재생하고 `SwordEffectEmitter`는 접촉 감지만 담당한다. 새로운 공용 효과의 등록·교체는 이펙트 담당자에게 요청한다.

#### 씬 전환과 세션 종료

- 일반 Single 씬 전환은 기존 효과를 정리하고 새 씬의 세션을 자동 시작한다. 새 플레이어 생성 후 감각 관측자 연결도 갱신한다.
- 게임 세션 담당자가 전체 효과를 종료할 때 `EndSession()`을 호출한다. 다시 시작할 때 `BeginSession()`을 호출하며, 그 전에는 새 재생 요청이 거부된다.
- Additive 구성에서 효과 세션의 기준 씬을 변경하려면 해당 씬을 활성 씬으로 지정한 뒤 `BeginSession()`을 호출한다. 여러 씬별 독립 세션은 지원하지 않는다.
- 개별 캐릭터는 자신의 `CancelSwing()`만 호출한다. 전체 EndSession이나 다른 시스템의 풀 정리는 수행하지 않는다.
- 기본 효과는 Time.timeScale=0이면 진행하지 않는다. 행동 상태만 일시정지로 변경하는 경우에는 별도로 효과 처리 방침을 연결해야 한다.

#### 적용 확인과 문제 해결

먼저 `Assets/Scenes/EffectTest.unity`에서 연결 예시를 확인하고, 실제 씬에서도 아래 항목을 점검한다.

| 증상 | 확인할 내용 |
| --- | --- |
| BeginSwing이 false | Start 완료, 검 컴포넌트·양 끝점 활성 상태, Owner Root, EffectManager.IsReady |
| 재생 성공인데 안 보임 | 카메라 시야·Culling Mask, 월드 위치, OutlineVFX의 관측자·인지 영역 |
| 검기만 보이고 타격이 없음 | 대상 Collider·Contact Layers, 자기 소유 계층으로 잘못 제외됐는지 확인 |
| 타격이 중복됨 | 대상의 여러 Collider 또는 대상 코드의 중복 PlayHit 호출 |
| 검기가 계속 남음 | 정상 종료에 EndSwing, 취소에 CancelSwing이 연결됐는지 확인 |
| Effect session is not ready | Game 초기화, EndSession 이후 BeginSession 여부 |
| No prefab registered / Library 검증 오류 | 이펙트 담당자에게 ID·Library 연결과 Console 메시지 전달 |

#### 연결 및 협업

- 플레이어·애니메이션 담당자는 검 참조와 베기 구간을 연결하고, 적·맵 담당자는 대상 Collider를 구성한다. 실제 캐릭터에서 취소·무기 교체·비활성화·씬 전환을 함께 점검한다.
- 프리팹·EffectLibrary·외형 변경은 이펙트 담당자 영역이다. 기존 `Assets/Resources/Effects/EffectLibrary.asset`과 `Assets/Resources/Prefabs/GameManagers/EffectManager.prefab`을 재사용하며, 씬별 복사본은 만들지 않는다.
- 발자국·파동은 [감각 표현](감각_표현.md), Canvas 효과·UI 연출은 각 담당자의 시스템에서 처리한다.
- 승인 필요 사항 및 결과: 이 문서는 구현된 호출 계약을 안내한다. 다른 담당자의 코드·씬·전투 판정은 자동으로 수정하거나 연결하지 않는다.
