# 사운드를 활용한 적 공격 패턴 구현 계획

- 작성일: 2026-10-12
- 현재 상태: 3단계 근접 적 하나의 두 박동 공격 구현·컴파일 확인 완료. 실제 재생·교전 검증은 최종 검증으로 이월
- 다음 작업: 사용자 피드백 우선 반영. 사용자가 4단계를 요청하면 행동별 음성·피격·패링 연결 정리 진행
- 작성 근거: 사용자가 두 심장박동으로 다음 공격을 예측하는 설계를 긍정적으로 평가하고, 구현 단계를 나누어 기억해 달라고 요청했다.
- 현재 요청의 범위: 3단계 선택적 두 박동 전조·기합·취소·Inspector 표시 구현 및 기준 SingleMelee 프리팹·공통 신호 설정 저장. 다른 공격 패턴과 보스·씬·FMOD 원본·Bank는 변경하지 않는다.
- 이 문서는 실행된 기능명세가 아니라 향후 작업 계획이다. 각 단계 구현 후 해당 기존 기능명세에 실제 변경과 검증 결과를 반영한다.

## 합의한 설계 기준

- 공격 전조 시간 T를 공격마다 1~2초 사이에서 한 번 선택한다. T는 첫 심장박동부터 실제 공격 시작까지의 시간이며, 반복 공격 간격과 구분한다.
- 시작 시 첫 박동, T/2에 두 번째 박동, T에 실제 공격을 실행한다. 한 공격 안에서 간격을 다시 추첨하지 않는다.
- 예: T=1.4초이면 0초 박동 → 0.7초 박동 → 1.4초 공격이다.
- 실제 반복 공격 간격에는 전조·실행·후딜과 필요한 패턴별 사용 제한이 포함된다. 기존 쿨타임이 전조와 별도의 랜덤 대기로 중복 적용되지 않게 한다.
- EnemyAttackVoice는 실제 공격 직전, EnemyAttack은 실제 공격 시작에 재생한다. 음성 종료를 기다리느라 공격을 지연하지 않는다.
- 전조와 실제 공격 예약은 하나의 시작 시각을 기준으로 관리한다. 독립된 사운드 코루틴과 공격 코루틴이 서로 다른 시간을 사용하지 않는다.
- 중단을 유발하는 피격·패링 경직·사망·대상 상실·비활성화 시 남은 박동과 음성 예약을 정리한다. 재시작은 첫 박동부터 한다.
- 일반 적의 기존 전조 시점 고정 조준, 사거리·우선순위 선택, 좌우 베기, 피해량과 방어 규칙을 유지한다. 박동에 맞춘 패링의 문제가 확인되면 원인을 먼저 측정하고 직접 관련된 부분만 조정한다.
- 먼저 일반 근접 적 하나에서 리듬과 판정의 관계를 검증한 뒤 다른 공격과 보스로 확장한다.

## 사운드 의미와 연결 조건

| 이벤트 | 연결 조건 |
| --- | --- |
| BossBGM | 보스방 진입 시 시작하여 방 체류 중 루프. 원본 음원 looping=true는 확인했으나 최신 Bank 이벤트는 여전히 단발로 표시된다. 연속 이벤트 루프의 실제 재생은 최종 검증 때 확인한다. |
| EnemyPrepare | 발견 후 접근 시작에 한 번, 실제 돌진 시작에 재생. 일반 공격 준비·원거리 준비·피격·패링·스턴의 대체 음성으로 사용하지 않는다. |
| EnemyHeartbeat | 공격 준비 시작 및 T/2에 각각 한 번. 한 번의 호출이 의도한 한 박동 신호인지 청취한다. |
| EnemyAttackVoice | 실제 공격 직전의 보조 음성. 원거리 준비 음성과 역할을 구분한다. |
| EnemyRangedAttackVoice | 원거리 시전 준비 시작. 첫 박동을 가리지 않게 믹싱한다. |
| EnemyDamaged | 실제 피해 적용 후 생존한 적의 고통 음성. 기존 검 적중 효과음은 유지한다. 치명타와 무적 중 차단된 피해에는 일반 고통 음성을 재생하지 않는다. |
| EnemyGetParryed | 정확한 플레이어 패링에 당한 공격자의 위치에서 한 번. 일반 가드나 보스가 플레이어를 쳐내는 사건에는 재생하지 않는다. |

### 1단계 — 현황 및 FMOD 이벤트 검증

- 구현 시작 당시 브랜치, 기존 작업과 수정 대상의 충돌을 확인한다. AGENTS.md의 브랜치별 Git CLI 허용 범위를 따른다. 이 문서 작성 당시 브랜치는 dev여서 Git CLI는 사용하지 않았다.
- docs/FEATURE_SPEC.md와 적 공격 패턴·사운드 중앙 편집·적 전투 및 체력·사운드 중심 보스전 명세의 현재 규칙을 확인한다. 오래된 기록보다 현재 코드와 에디터 값을 우선하여 기록한다.
- Unity CLI·Pipeline으로 해당 프로젝트를 명시해 연결한다. 설정·도구·패키지를 임의로 설치하거나 변경하지 않는다.
- 6개 새 이벤트의 GUID·경로·Bank 포함 여부·3D 설정·샘플 로드를 확인한다. BossBGM의 루프 관련 원본 및 Bank 속성을 확인한다. 실제 재생·청취는 아래 사용자 검증 규칙에 따라 최종 검증으로 이월한다.
- 심장박동 한 호출의 실제 신호, 시작 무음, 길이를 확인한다. 캐시 length=0을 실제 길이 0으로 해석하지 않는다.
- 기존 EnemyPrepare 호출뿐 아니라 다른 SoundId가 같은 이벤트를 가리키는 연결도 조사한다.
- 완료 기준: 이벤트별 확인 결과와 미확인 항목, 기준 근접 적의 설정·협업 충돌 여부가 기록돼 있다. 다음 단계에서 사용할 이벤트를 찾을 수 있다.

### 2단계 — 새 이벤트 중앙 등록 및 편집 연결

- SoundId에 새 ID를 추가할 때 기존 enum의 숫자와 기존 직렬화 연결을 유지한다.
- SoundLibrary와 기존 중앙 편집 흐름에 새 이벤트·음량·사용 여부를 등록한다. EnemySoundSettings 및 CombatSoundProfile은 역할에 맞춰 필요한 항목만 확장한다.
- 심장박동·공격 음성·공격 효과음을 동시에 다룰 수 있게 한다. 현재 단일 _playingActionSound 추적으로 새 소리를 덮어쓰거나 취소 시 일부가 남지 않게 한다.
- 자연 종료와 강제 취소를 구분하고, 다른 적이나 플레이어의 소리를 함께 정지하지 않는다. 공격 취소 뒤 예약된 음성이 뒤늦게 나오지 않게 한다.
- 이동 중 효과음 제한과 BGM 음소거 경로가 새 신호를 가로막는지 확인한다.
- 완료 기준: 새 이벤트를 중앙 설정에서 독립 편집·재생할 수 있고 기존 효과음 연결이 유지된다. Unity 컴파일 오류가 없다.

### 3단계 — 근접 적 하나의 두 박동 공격 구현

- EnemyAttackBehaviour의 기존 Telegraph → Active → Recovery 흐름을 활용한다. 우선 기준 근접 적만 적용하고 검증 전 전체 프리팹의 전조를 일괄 변경하지 않는다.
- T의 최소·최대값과 음성 선행 시간을 필요한 Inspector 설정으로 제공한다. 실제 선택값은 EnemyAttackContext와 전조 진행 표시에도 반영한다.
- 전조 시작 시 T를 선택하고 t0, t0+T/2, t0+T에 첫 박동·두 번째 박동·공격을 실행한다. 음성 선행은 실제 공격 시각에서 역산한다.
- 프레임 지연 시 지나간 여러 신호를 한 프레임에 몰아 재생하는 문제가 생기는지 확인하고, 예측할 수 없는 공격이 나오지 않게 처리한다.
- 공격 취소·사망·비활성화·재활성화와 일시정지에서 시간 및 재생 예약을 정리한다. 게임 시간 정지 중에는 공격 단계가 진행되지 않아야 한다.
- 베기·후딜·필요한 사용 제한을 포함한 예상 반복 간격을 개발자가 확인할 수 있게 한다. 박동의 pitch 랜덤화로 같은 공격 안의 신호 길이가 달라지지 않게 한다.
- 완료 기준: 시간 예약·단일 실행·취소 처리의 구현과 컴파일 검증을 완료한다. 서로 다른 T의 실제 박동 간격, 취소 후 잔여 신호 및 세 번째 박자의 패링 성공은 최종 Play 검증 항목으로 기록하며 검증 전에는 동작 확인 완료로 표시하지 않는다.

### 4단계 — 행동별 음성·피격·패링 연결 정리

- EnemyDamageAudio의 발견·접근 신호는 유지하되 반복 공격 상태 전환으로 중복되지 않게 한다.
- 근접 준비의 임시 음성을 박동으로 대체하고 실제 공격 직전에 EnemyAttackVoice를 재생한다. 기존 EnemyAttack 및 좌우 베기 효과는 실제 공격 단계와 연결한다.
- 비치명 실제 피해에는 EnemyDamaged를 추가한다. 공통 피격 프로필을 단순 교체하여 플레이어도 적의 고통 음성을 내는 변경을 피한다.
- 기존 패링 성공 사건의 공격자를 사용하여 EnemyGetParryed를 한 번 재생한다. 기존 패링 효과음은 유지한다.
- 스턴을 무조건 패링 음성으로 치환하지 않고 실제 피해·패링 원인으로 구분한다. 자동 반격으로 후속 피해가 발생하면 패링 음성과 피해 음성의 중첩·잘림도 확인한다.
- 완료 기준: 발견·일반 피격·치명타·사망·가드·패링·무적 차단에서 올바른 음성이 한 번씩 발생한다. EnemyPrepare가 허용된 두 상황에만 남는다.

### 5단계 — 일반 원거리·돌진 및 복수 패턴으로 확장

- 원거리 준비 시작에 EnemyRangedAttackVoice를 재생하고, 세 번째 박자에 기존 투사체를 발사한다. 발사와 플레이어 도착 시점을 구분한다.
- 일반 돌진은 두 박동 뒤 세 번째 박자에 이동·접촉 판정을 시작하며 EnemyPrepare를 실제 돌진 신호로 사용한다.
- EnemyRhythmChargeAttack의 기존 탓·탓·타탓 실행 리듬과 이동 거리는 유지한다. 두 박동을 공격 진입 예고로 적용하되 내부의 각 이동을 임의로 새 1~2초 공격으로 재정의하지 않는다.
- EnemyAttackSelector의 거리·우선순위·단일 실행 규칙을 유지한다. 복수 패턴 전환에서도 이전 신호 예약이 남지 않게 한다.
- 완료 기준: 근접·원거리·일반 돌진·박자 돌진이 의도한 박자에 실행되고, 패턴 전환 및 경직 후 재시작이 첫 박동부터 이루어진다. 기존 피해·투사체·NavMesh 이동 동작이 유지된다.

### 6단계 — 보스 사운드·박동·보스방 BGM 연결

- BossController의 별도 원거리·돌진 코루틴 및 BossMeleeAttack을 확인하여 일반 적과 같은 박동 시간 계약을 적용한다.
- 현재 보스의 패턴 순서·연속 발사 수·재배치·회복·무적·쳐내기 규칙을 보존하고 전조·사운드에 직접 관련된 부분만 변경한다.
- 연속 발사에서는 각 발사의 두 박동과 발사 시각을 같은 기준으로 관리한다. 준비·발사 간격·랜덤 대기가 겹쳐 불필요하게 늘어나지 않게 하며, 한 연속 패턴 안에서는 일정한 간격을 사용한다.
- BossPresentation의 임시 EnemyPrepare 원거리·정면승부·스턴 연결을 실제 행동의 새 음성으로 정리한다. 발견·돌진 외의 EnemyPrepare 사용을 남기지 않는다.
- 보스방 진입 사건에 BossBGM을 한 번 연결한다. 보스 객체가 사라지거나 비활성화돼도 방 체류 중 BGM이 의도치 않게 종료되지 않도록 수명을 보스방 진입·퇴장 흐름에 연결한다.
- 방 퇴장·씬 전환·재시작에서 BGM 정리와 기존 배경음 복귀를 확인한다. 보스 사망 이후 방 안에서의 재생은 방 체류 중 유지하는 기본안으로 처리한다.
- 완료 기준: 보스 공격·방어·피격 중 잔여 전조나 중복 음성이 없고, 보스방 BGM은 한 인스턴스로 반복된다. 기존 보스 교전 규칙의 회귀가 없다.

### 7단계 — 통합 교전·청취 검증 및 명세 반영

- Unity CLI·Pipeline으로 컴파일과 Play 동작을 확인한다. 테스트 코드는 작성하지 않는다.
- 실제 입력으로 빠른 전조·느린 전조·좌우 베기·패링·회피·자동 반격·피격 취소를 확인한다. 코드의 시간 계산 확인과 스피커 청취 확인을 구분해 기록한다.
- 다수 적, BGM과 발소리의 동시 재생에서도 두 박동을 구분할 수 있는지 확인하고 중앙 음량·우선순위를 조정한다. 다른 적의 소리를 전역 정지시키지 않는다.
- 씬 전환·일시정지·사망·재시작·비활성화 후 음성 예약 및 BGM 수명을 확인한다.

- 리듬 공격의 박동·기합·실행음 ID를 독립 보관하고 해당 적의 ID만 forceStop으로 정리한다. 비활성화와 취소뿐 아니라 다음 리듬 시작에서도 이전 꼬리를 정리한다. 정상 실행·후딜 전환은 자연 종료한다. 비리듬 공격의 기존 정지 동작은 유지한다.
- EnemySoundSettings에 박동(26)과 기합(27) 필드 및 EnemySoundStage.Heartbeat/AttackVoice를 추가했다. 기존 행동·발걸음 설정을 보존하여 다른 패턴의 재생 사건은 바꾸지 않았다.
- Enemy_SingleMelee.prefab의 MeleeStrike만 리듬 옵션을 켰다. 이를 상속한 씬 인스턴스에 적용되지만 씬 자체는 저장하지 않았다. 기존 베기 최대 0.24초·후딜 0.55초·쿨타임 0.4초 및 피해·좌우 효과·판정은 유지했다. Unity 프리팹 저장 시 기존 EnemyDamageAudio 기본 pitch=1도 명시됐으며 값은 변경되지 않았다.
- 새 EnemyAttackBehaviourEditor는 기본 Inspector와 다중 선택 편집을 유지하며 예상 반복 간격 및 최근 T·박동 간격을 표시한다. 기준 패턴의 계산값은 1.79~2.79초이며 별도 이동·다른 패턴·보스 대기는 포함하지 않는다.
- 검증: Unity 컴파일 completed·failed=false·errors=[]·compilationFailed=false. Editor에서 공통 신호 연결, 대상 프리팹 옵션, 실제 CustomEditor 생성과 Label 값을 확인했다. SingleRanged·MultiPattern·RhythmCharge·DeflectableMelee·Boss_SoundDuel의 리듬 옵션은 false였다. BossBattle 씬은 isDirty=false였다. 소스와 프리팹 차이를 검토했고 기존 프리팹 값과 2단계 작업을 보존했다.
- 갱신 명세: docs/features/적_공격_패턴.md. 실제 공격 실행·청취·취소·저프레임·패링·회피는 미확인이며 최종 검증으로 이월한다. Play 및 테스트 코드 추가 없음, 누적 플레이테스트 0회. 4단계는 시작하지 않았다.

### BossBGM 사용자 피드백 확인

- 사용자는 루프 Bank 연결 후 재빌드했다고 알렸고 이벤트 경로를 event:/Ambience/BossBGM으로 확인해 줬다. 기존 Library의 이벤트 경로·GUID와 일치하므로 연결을 바꾸지 않았다.
- 이번 작업에서 현재 설정이 참조하는 FMODProject/week06-blindblade/Build/Desktop/BGM.bank를 독립 무음 시스템으로 다시 조회한 결과 load/getEventByID/isOneshot은 OK, isOneshot=true, 길이는 38400ms였다. 이 파일의 SHA256은 1단계와 같은 CA86E00F4A4C97370155C50F99437E889CB2FD5FD54B765B305631C25E63DD8C였다.
- 사용자 재빌드 보고와 현재 프로젝트에서 읽은 파일의 결과를 구분한다. 원본 이벤트 경로는 확정했지만 새 루프 빌드의 반영 위치와 실제 연속 루프는 미확인이다. 이 문제로 근접 리듬 구현을 중단하거나 FMOD 원본·설정·Bank를 임의로 변경하지 않았다. 보스 연결과 최종 검증 때 다시 확인한다.

## 사용자 진행 및 검증 지침 — 2026-10-12

- 사용자가 요청한 단계만 진행하고, 다음 단계를 자동으로 구현하지 않는다.
- 단계 진행 중 사용자가 피드백을 주면 해당 피드백을 먼저 반영한다. 그 뒤 사용자가 다음 단계를 요청하면 진행한다.
- 단계별로 Play를 반복하지 않는다. 반드시 필요한 경우에만 구현 작업을 모두 마친 뒤 첫 플레이테스트를 한 번 진행한다. 첫 회차에서 문제가 발견되면 수정 후 한 번 추가 검증하며 전체 최대 두 회로 제한한다.
- 1~6단계에서는 읽기 전용 조회·Bank 속성·샘플 로드·정적 검토 및 변경에 필요한 컴파일 검증을 우선한다. 실제 입력·교전·청취는 최종 통합 검증으로 모아 수행하고 확인 전에는 미확인으로 기록한다.
- 누적 플레이테스트 횟수: 0회. 독립 무음 Bank 조회와 샘플 로드는 이벤트를 start하지 않았으며 게임 플레이테스트가 아니다.
- 후속 확인 항목: BossBGM 새 루프 Bank의 실제 반영과 심장박동 한 호출의 신호 단위. BossBGM 경로 확인 피드백은 위 3단계 기록에 반영했다. 다음 단계 구현을 막는 승인 요청이 아니라 확인 결과이며, 추가 사용자 피드백이 오면 우선 반영한다.

## 이어서 작업하는 규칙

- 이후 이 기능 작업을 시작할 때 이 문서와 관련 최신 명세를 먼저 읽는다.
- 단계 번호로 진행을 설명하고, 완료 기준을 통과한 단계만 완료로 표시한다. 부분 구현이나 검증 불가 상태는 진행 중 또는 미확인으로 남긴다.
- 각 단계가 끝나면 표의 상태, 현재 상태, 다음 작업과 검증 근거를 갱신한다.
- 새 사용자 지시가 들어오면 적용되는 설계와 단계를 갱신하고 완료된 작업을 불필요하게 다시 수행하지 않는다.
